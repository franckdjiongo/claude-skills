# Codex custom agent reference

Read by the Codex variant of this skill. A Codex custom agent is one TOML file at
`.codex/agents/<name>.toml` (project) or `~/.codex/agents/<name>.toml` (user).

## Keys

Checked against codex-cli 0.162.0 (its agent-role loader and config schema) and the working agents
of `temps-chantier-code-app/.codex/agents/`. Re-check with the installed version when a key behaves
unexpectedly.

| Key | Required | Notes |
|---|---|---|
| `name` | yes | Non-empty. Equal to the file name without `.toml`. |
| `description` | yes | Not blank. What the agent does, when to spawn it, what it returns. |
| `developer_instructions` | yes | Not blank. The agent's job description. |
| `nickname_candidates` | no | List of display names: at least one, no blank or duplicate entry, ASCII letters, digits, spaces, hyphens and underscores only. |
| `model` | no | Only as a projection of a routing file that registers the agent (see SKILL.md, "Model routing"). |
| `model_reasoning_effort` | no | `low`, `medium` or `high` for a sub-agent. |
| `sandbox_mode` | no | `read-only` or `workspace-write`. `danger-full-access` only with a stated reason. |

The file is read as a Codex config layer, so other config keys are parsed too. Use them only when the
user asks for one and you have checked it against the installed codex-cli.

## Pitfalls

- **Regular file only.** A symlinked agent shows up in the catalogue but `spawn_agent` refuses it
  ("agent type is currently not available"). A copy fed from another repo starts with
  `# GENERATED by <source-project>/<path>`.
- **Multi-line strings.** `"""…"""` is a basic string: a backslash starts an escape and `"""` ends it.
  If the instructions contain backslashes (regexes, Windows paths), use a literal string `'''…'''`
  instead, which must not contain `'''`.
- **Parse before declaring done:**
  `python3 -c "import tomllib,sys; d=tomllib.load(open(sys.argv[1],'rb')); print(sorted(d))" <path>`.
- **Discovery.** Start a new Codex session after writing the file.
- **Spawning.** The parent uses `spawn_agent` with `agent_type: "<name>"` and without a full-history
  fork: a full-history fork inherits the parent's agent type.

## Templates

### Read-only researcher

```toml
name = "code-explorer"
description = "Read-only exploration specialist. Spawn to answer one bounded question about this repository with file and line evidence. Returns VERIFIED, NOT_FOUND or BLOCKED."
sandbox_mode = "read-only"
developer_instructions = """
You answer one bounded exploration question for the parent session.

1. Restate the question in one sentence.
2. Search with `rg` first, then read only the smallest slice that answers it.
3. Stop when the question is answered.

Rules: read-only; do not spawn other agents; if a file or symbol is not found, say `not found`.

Report: first line VERIFIED, NOT_FOUND or BLOCKED, then Evidence (paths and lines), Answer, Gaps.
"""
```

### Reviewer

```toml
name = "diff-reviewer"
description = "Independent reviewer of a git diff for correctness and regressions. Spawn with the base ref and the scope to review. Returns PASS, FINDINGS or BLOCKED on the first line."
sandbox_mode = "read-only"
developer_instructions = """
You review the diff the parent names (`git diff <base>...HEAD`), nothing else.

1. Read AGENTS.md and the files the diff touches.
2. Look for correctness bugs, regressions and missing tests. Verify in the code before claiming.
3. Return an empty finding list rather than cosmetic remarks.

Report: first line PASS, FINDINGS or BLOCKED, then one entry per finding: file:line, severity, problem, fix.
"""
```

### Implementer

```toml
name = "slice-implementer"
description = "Implements one bounded change the parent specifies, with its tests. Spawn with the goal, the files in scope and the validation command. Returns changed files and the validation output."
sandbox_mode = "workspace-write"
developer_instructions = """
You implement exactly the change the parent describes, inside the files it names.

1. Read AGENTS.md, then the files in scope.
2. Make the change and add or update its tests.
3. Run the validation command the parent gave and read its real output.

Rules: stop and report if the change needs files outside the scope; do not commit; do not spawn other agents.

Report: changed files, behavior changed in one sentence, validation command and its output.
"""
```
