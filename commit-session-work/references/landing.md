# Landing session work on the primary branch through a pull request (push-enabled modes)

Read this when the mode is Scoped or Full-tree and session work must reach `PRIMARY_BRANCH`, whatever the source: the primary checkout, a session-created worktree, a detached session checkout, or a secondary branch attributable to the current task. Session work lands only through a pull request merged on the remote. Never merge, cherry-pick or commit it onto `PRIMARY_BRANCH` locally and push that branch.

## Classify the source

Classify the source as primary checkout, session-created secondary worktree, session-created branch, detached session worktree, or ambiguous/user-owned checkout. Use conversation evidence for ownership; never infer ownership only from a branch name or filesystem path. The remote must be a GitHub repository `gh` can reach with the account of the SSH alias; otherwise stop after the push of step 6 and report that the landing is pending.

## The ten steps

1. **Audit both sides.** Fetch first. Record source status, merge-base with `origin/PRIMARY_BRANCH`, source-only commits, untracked files, and exact Owned/Mixed/Unrelated paths.
2. **Validate at the source.** Run the repository-required gate and relevant targeted checks before committing.
3. **Commit on a work branch.** Stage only the selected scope in Scoped mode, or the full audited source tree in Full-tree mode, and commit it on a work branch, never on `PRIMARY_BRANCH`. A session worktree or session branch is already the work branch. If detached, create a uniquely named temporary local session branch (prefix in `SKILL.md`) at `INITIAL_HEAD`; never commit while detached. In the primary checkout, create that branch with `git switch -c <branch>` (the uncommitted work follows it), commit, push it at step 6, then `git switch "$PRIMARY_BRANCH"` at once: the primary checkout leaves its branch only for this commit and push. If that switch back is refused (a Mixed file keeps unstaged hunks), do not force it: stay on the work branch and report it. Leave unrelated changes unstaged and do not remove a worktree while they remain.
4. **Select exact commits.** The PR carries only the commit or ordered commit series attributable to the session. When the work branch also holds an unreviewed or unrelated source-only commit, create a fresh session branch from `origin/PRIMARY_BRANCH` in a scoped `mktemp -d` worktree and cherry-pick the exact attributable commits oldest-to-newest onto it. To land a user-owned branch the user named, open the PR from a new session branch at its exact head, so the merge deletes only that session branch. Never open a PR that imports unrelated commits.
5. **Sync with the primary branch.** When the work branch is behind `origin/PRIMARY_BRANCH`, merge `origin/PRIMARY_BRANCH` into it (never rebase a pushed branch) and rerun the gate. A conflict that cannot be resolved from session evidence is a blocker.
6. **Push the work branch.** `git push -u origin <branch>` normally, then verify the remote-tracking branch equals the local `HEAD`. Never push `PRIMARY_BRANCH`.
7. **Open the PR.** Meet the repository's PR prerequisites first: on this machine a non-draft PR needs an `adversarial-pr-review` PASS on its exact `HEAD`. Then `gh pr create --base "$PRIMARY_BRANCH" --head <branch>` with a title and body derived from the commits, without AI attribution. Wait for the checks (`gh pr checks <n> --watch`): a pending check is not a green one.
8. **Merge.** When the `ship-pr` skill is available, invoke it naming this PR. It checks mergeability, green checks and the review gate, merges with `--match-head-commit`, deletes the remote branch, syncs the checkout that owns `PRIMARY_BRANCH`, reruns the gate on the result, and redeploys when the repository defines it. Where `ship-pr` does not exist (Codex), do the same by hand:
   - `gh pr view <n> --json state,isDraft,mergeable,mergeStateStatus,statusCheckRollup,baseRefName,headRefOid`: open, not draft, `MERGEABLE`, no blocking merge state, every check green, base `PRIMARY_BRANCH`, head equal to the pushed commit.
   - `gh pr merge <n> --merge --delete-branch --match-head-commit <headRefOid>` (match a squash or rebase convention only when the primary branch's history shows one).
   - Sync the checkout that owns `PRIMARY_BRANCH` (`git worktree list --porcelain`; none: a scoped `mktemp -d` integration worktree, removed afterwards): `git fetch`, then `git pull --ff-only`. Never stash, reset or discard another checkout's work to make the sync pass; overlapping dirty paths are a blocker.
   - Run the repository gate on the synced primary branch: a green source gate does not replace it.
   - Redeploy only when the repository defines a redeploy and the merged diff touches what it serves, then verify the new code is served if the repository names a way.

   A red or pending check, a missing review PASS, a conflict or a red gate after the merge stops the landing: report it with the PR URL. An unmerged PR stays open.
9. **Prove retention.** Record the merge commit (`gh pr view <n> --json mergeCommit`). Verify the PR head commit is an ancestor of the synced `PRIMARY_BRANCH`; after a squash or rebase merge, compare stable patch IDs plus the selected file content instead. Confirm every Owned file and untracked artifact selected for transfer is represented on the target.
10. **Clean session artifacts.** Remove what the merge made obsolete and `ship-pr` did not already remove. Remove a session-created source or integration worktree only after retention proof and only when no unrelated or ambiguous content remains. Inventory tracked, untracked, and ignored files first. Prefer normal `git worktree remove`; use `--force` only when content comparison proves every remaining tracked change is an exact retained duplicate and every untracked/ignored artifact is known disposable or retained elsewhere. Run `git worktree prune` and `git fetch --prune`. Delete only a local branch created by this skill, after no worktree uses it and retention is proven: `git branch -d` when its head is an ancestor of the primary branch; after a squash, rebase or cherry-pick, `git branch -D` is permitted only for that exact branch because patch-ID and content proof replace ancestry. Never force-delete a pre-existing/user branch, and never delete a remote branch other than the merged PR's own.
