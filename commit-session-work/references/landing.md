# Landing session work on the primary branch through a pull request (push-enabled modes)

Read this when the mode is Scoped or Full-tree and session work must reach `PRIMARY_BRANCH`, whatever the source: the primary checkout, a session-created worktree, a detached session checkout, or a secondary branch attributable to the current task. Session work lands only through a pull request merged on the remote. Never merge, cherry-pick or commit it onto `PRIMARY_BRANCH` locally, never push `PRIMARY_BRANCH`, and never move the primary checkout off `PRIMARY_BRANCH`.

## Classify the source and probe the remote

Classify the source as primary checkout, session-created secondary worktree, session-created branch, detached session worktree, or ambiguous/user-owned checkout. Use conversation evidence for ownership; never infer ownership only from a branch name or filesystem path.

Before step 6, run `gh repo view <owner/repo> --json name` for the repository of the push remote. `gh` holds one account at a time on this machine: if the probe fails (no GitHub remote, `Repository not found`, 404), do not push, never run `gh auth switch`, and report the landing as pending with the committed work branch.

## The ten steps

1. **Audit both sides.** Fetch first. Record source status, merge-base with `origin/PRIMARY_BRANCH`, source-only commits, untracked files, and exact Owned/Mixed/Unrelated paths.
2. **Validate at the source.** Run the repository-required gate and relevant targeted checks before committing.
3. **Commit on a work branch, in a session worktree.** Stage only the selected scope in Scoped mode, or the full audited source tree in Full-tree mode, and commit it on a work branch, never on `PRIMARY_BRANCH`. A session worktree or session branch is already the work branch. If detached, create a uniquely named temporary local session branch (prefix in `SKILL.md`) at `INITIAL_HEAD`; never commit while detached. When the source is the primary checkout, do not switch it: create the branch in a session worktree (`git worktree add "$(mktemp -d)/wt" -b <branch> HEAD`), bring over exactly the selected content (whole Owned files and selected untracked artifacts copied, deletions applied with `git rm`, only the attributable hunks of a Mixed file applied with `git apply`), check that each landed path matches the selected content, and commit there. The primary checkout keeps all its changes and its branch. Leave unrelated changes unstaged and do not remove a worktree while they remain.
4. **Select exact commits.** The PR carries only the commit or ordered commit series attributable to the session. When the work branch also holds an unreviewed or unrelated source-only commit, create a fresh session branch from `origin/PRIMARY_BRANCH` in a scoped `mktemp -d` worktree and cherry-pick the exact attributable commits oldest-to-newest onto it. To land a user-owned branch the user named, open the PR from a new session branch at its exact head, so the merge deletes only that session branch. Never open a PR that imports unrelated commits.
5. **Sync with the primary branch.** When the work branch is behind `origin/PRIMARY_BRANCH`, merge `origin/PRIMARY_BRANCH` into it (never rebase a pushed branch) and rerun the gate. A conflict that cannot be resolved from session evidence is a blocker.
6. **Review, then push the work branch.** Work in the checkout whose `HEAD` is the work branch and whose tree is clean (the session worktree; for a work branch with no clean checkout, `git worktree add "$(mktemp -d)/wt" <branch>`). Meet the repository's PR prerequisites there: on this machine a non-draft PR needs an `adversarial-pr-review` PASS on its exact `HEAD`, run with `review-run.mjs … --repo <that checkout>`. Then `git push -u origin <branch>` normally and verify the remote-tracking branch equals the local `HEAD`.
7. **Open the PR from that checkout.** `cd <that checkout>` first (a standalone command, or `cd <dir> && gh pr create …` in one command), then `gh pr create --base "$PRIMARY_BRANCH" --head <branch>` with a title and body derived from the commits, without AI attribution. Wait for the checks (`gh pr checks <n> --watch`): a pending check is not a green one.
8. **Preflight, merge, sync.**
   - **Preflight the primary checkout** (the one that owns `PRIMARY_BRANCH` in `git worktree list --porcelain`), after `git fetch`. Stop, leave the PR open and report the landing pending when: `git rev-list "origin/$PRIMARY_BRANCH..$PRIMARY_BRANCH"` is non-empty and `git cherry <PR head> "$PRIMARY_BRANCH"` shows any `+` (local primary holds a commit the PR does not carry); or a dirty path from `git status --porcelain` is in `git diff --name-only "$PRIMARY_BRANCH" "origin/$PRIMARY_BRANCH"`, or is a PR file that is not a landed Owned/Mixed path of this session.
   - **Stage the landed versions there.** For each landed path still dirty in the primary checkout, stage exactly the work-branch version: `git add -- <path>` when the working file equals it, else `git update-index --cacheinfo <mode>,"$(git rev-parse <branch>:<path>)",<path>` for a Mixed file. The fast-forward then keeps those entries and the unrelated unstaged hunks.
   - **Merge.** When the `ship-pr` skill is available, invoke it naming this PR. From this skill, ship-pr's stash, `merge --no-ff` and push fallbacks never run, and neither does its redeploy: its sync must be a plain fast-forward, otherwise stop. Where `ship-pr` does not exist (Codex), do its checks by hand:
     - `gh pr view <n> --json state,isDraft,mergeable,mergeStateStatus,statusCheckRollup,baseRefName,headRefOid`: open, not draft, `MERGEABLE`, no blocking merge state, every check green, base `PRIMARY_BRANCH`, head equal to the pushed commit.
     - When the claude-skills repository is present, run `node <claude-skills>/ship-pr/scripts/review-gate.mjs --repo <owner/name> --pr <n>`: continue only on exit 0 with output starting `PASS` or `NOT-ENROLLED`, and only while `baseRefName` and `headRefOid` still equal the printed base and head.
     - `gh pr merge <n> --merge --delete-branch --match-head-commit <that head>` (match a squash or rebase convention only when the primary branch's history shows one).
     - Sync with `git fetch` then `git merge --ff-only "origin/$PRIMARY_BRANCH"`. If no checkout owns `PRIMARY_BRANCH`, use a scoped `mktemp -d` integration worktree, removed afterwards; if the local primary branch is missing but `origin/PRIMARY_BRANCH` exists, create the local tracking branch only in that integration worktree.
   - **Realign or stop.** If the fast-forward fails because local primary holds commits, run `git cherry "origin/$PRIMARY_BRANCH" "$PRIMARY_BRANCH"`: only `-` lines (every local commit is patch-equivalent to the merged PR) allow `git reset --keep "origin/$PRIMARY_BRANCH"`; any `+`, or a refused reset, is a blocker. Never push `PRIMARY_BRANCH`.
   - **Gate, no redeploy.** Run the repository gate on the synced primary branch: a green source gate does not replace it. This skill never redeploys: when the repository defines a redeploy and the merged diff touches what it serves, report the redeploy as pending.

   A red or pending check, a missing review PASS, a conflict, a failed preflight or a red gate after the merge stops the landing: report it with the PR URL. An unmerged PR stays open.
9. **Prove retention.** Record the merge commit (`gh pr view <n> --json mergeCommit`). Verify the PR head commit is an ancestor of the synced `PRIMARY_BRANCH`; after a squash or rebase merge, compare stable patch IDs plus the selected file content instead. Confirm every Owned file and untracked artifact selected for transfer is represented on the target.
10. **Clean session artifacts.** Remove what the merge made obsolete and `ship-pr` did not already remove, including the `mktemp -d` worktrees of steps 3, 4, 6 and 8. Remove a session-created source or integration worktree only after retention proof and only when no unrelated or ambiguous content remains. Inventory tracked, untracked, and ignored files first. Prefer normal `git worktree remove`; use `--force` only when content comparison proves every remaining tracked change is an exact retained duplicate and every untracked/ignored artifact is known disposable or retained elsewhere. Run `git worktree prune` and `git fetch --prune`. Delete only a local branch created by this skill, after no worktree uses it and retention is proven: `git branch -d` when its head is an ancestor of the primary branch; after a squash, rebase or cherry-pick, `git branch -D` is permitted only for that exact branch because patch-ID and content proof replace ancestry. Never force-delete a pre-existing/user branch, and never delete a remote branch other than the merged PR's own.
