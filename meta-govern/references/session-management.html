Session Management — Compact, Clear, Rewind, Handoff

Source: Progressive Context Disclosure for Claude Code on Windows.md Session Workflow section, Temps Chantier compaction discipline observed in postcompact-reinject.mjs.

# The 4 session operations

Operation When to use Effect
/compact Window approaching limit, but context still relevant Compresses prior turns; PostCompact hook fires
/compact <topic> Want to keep context focused on a specific thread Compaction with focus prompt — only that topic survives
/clear Context poisoned, hallucinated state, pivoting Wipes context; CLAUDE.md re-loads, nothing else
/rewind Want to go back to a specific moment in this session Visual UI; pick the turn
Summarize then clear Want a compressed save before wiping Tell Claude "summarize from here", copy summary, then /clear

# When to compact (proactive)

Per Doc 4: Proactive compaction at 50% utilization beats reactive at 90%.

Rough heuristic: compact when:

  • Context window is half full
  • You're about to start a new logical phase
  • Subagent dispatches are starting to fail
  • Claude is forgetting earlier instructions

# What survives compaction

Only:

  1. CLAUDE.md (re-loaded fresh)
  2. PostCompact hook output (re-injected as additionalContext)
  3. Claude's own summary of compacted content

What is LOST:

  • Skill bodies that were loaded
  • Subagent context
  • Tool call history
  • Any in-context state that wasn't in CLAUDE.md or PostCompact output

# The compaction recovery pattern

To survive compaction safely, the user needs:

# 1. CLAUDE.md "Après compaction" section

## Après compaction

Re-read this file. If `HANDOFF.md` exists at project root, read it. Resume work
on the active branch. If you're mid-plan-execution, see HANDOFF.md `Active plans`
section.

# 2. PreCompact hook generating HANDOFF.md

The precompact-handoff.mjs hook fires before compaction and writes HANDOFF.md:

# HANDOFF — Generated YYYY-MM-DD HH:MM

## Branch
plan/payment-flow-v2

## Modified files (top 40)
- src/payment/...
- ...

## Active plans
- docs/plans/2026-05-06-payment-flow-plan.md (3/8 tasks complete)

## Trigger reason
Context window at 80%

## Resume instructions
1. Read this file
2. Read CLAUDE.md
3. Read the active plan
4. Continue from task 4

## Discipline reminders
- Foreground reviews only
- Apply delta as last task
- File-size cap 300 lines

# 3. PostCompact hook re-injecting discipline

The postcompact-reinject.mjs hook fires after compaction and re-injects critical rules:

// Detects plan execution context
const isInPlanExecution = (
  fs.existsSync('HANDOFF.md') &&
  /plan\//.test(currentBranch) &&
  hasUncheckedPipelineTasks
);

if (isInPlanExecution) {
  return {
    additionalContext: `
# Plan execution discipline (reinjected after compaction)

1. NEVER dispatch reviewers in background.
2. Dispatch != done. A subagent returning means the WORK is done; the FINDINGS still need disposition.
3. Groups are barriers. Don't start group N+1 until group N is fully reviewed.
4. Review fix loop: every finding gets Fixed (with re-run) or Deferred (with new DEFERRED-XXX entry).
5. Every finding needs a disposition. No silent dropping.
`
  };
}

This is the ONLY way to enforce discipline that must survive compaction.

# Handoff file structure (BOOTSTRAP installs)

HANDOFF.md is auto-generated, never manually edited. Located at project root.

If user manually edits, the next PreCompact will overwrite. To preserve, save under a different name (docs/handoffs/YYYY-MM-DD-handoff.md).

# /compact vs /compact 

/compact
   → Compresses everything. Good for general window pressure.

/compact "We're working on payment flow Phase 2 implementation. Keep payment-related context."
   → Focused compaction. Other unrelated context is heavily compressed.

Use focused when:

  • You've been working on multiple topics this session
  • Some topics are done, others ongoing
  • You want to surgically keep specific context

# /clear vs /compact

Symptom Use
Window full, work still good /compact
Hallucinated state ("Claude thinks file X has Y but it doesn't") /clear
Pivoting to entirely new task /clear
Want to debug Claude's behavior /clear (rules out memory poisoning)
Context still mostly relevant, just verbose /compact

# /rename before /clear (preserve session ID)

If you're going to /clear but want to find this session later:

  1. /rename "investigation-XYZ-2026-05-07"
  2. /clear
  3. Later: /resume <session-id> to come back

# Session-state files (BOOTSTRAP installs)

Located in .claude/tmp/:

  • workflow-state.json — last edit + last validate timestamps
  • last-env-check.json — SessionStart hook 24h cache
  • last-full-scan.json — daily-drift-alert 24h cache (palier 3+)

These should be:

  • gitignored
  • mkdir-p'd at first write
  • Cleaned by npm run clean (optional)

# Anti-patterns

Anti-pattern Symptom Fix
No PreCompact hook After /compact, Claude has no memory of plans/branches Install precompact-handoff.mjs
No PostCompact hook for plan execution After /compact, Claude restarts dispatch dispatch loops without discipline Install postcompact-reinject.mjs with plan-detection
Compaction-critical rules not in CLAUDE.md Lost on /compact Move to CLAUDE.md OR ensure PostCompact reinjects them
/clear without /rename first Lost session record /rename first if you might want to resume
HANDOFF.md committed to git Pollutes history Add to .gitignore
Manually editing HANDOFF.md Next PreCompact overwrites Save under docs/handoffs/ if you need to keep

# When the user crosses 80% utilization

meta-govern can detect this via session metadata (if exposed) or rely on the user's intuition. Standard pattern:

  1. Claude proactively says: "Context is at 80%; I recommend /compact <topic> before continuing."
  2. User compacts.
  3. PostCompact hook re-injects discipline.
  4. Continue.

# Periodic compaction in long sessions

For multi-hour sessions:

  • Compact every ~2 hours of active work
  • Each compaction is an opportunity to re-state goals
  • After compact: read CLAUDE.md, read HANDOFF.md, restate current task

# In meta-govern modes

Mode Compaction expectation
BOOTSTRAP Should fit in single context window for moderate projects
AUDIT Read-only; no writes; should fit easily
MIGRATE Long-running; compaction likely → ensure HANDOFF discipline
EVOLVE Reading lessons-log + own files; should fit

For long migrations, meta-govern checkpoint-commits between phases so /compact recovery is trivial.
