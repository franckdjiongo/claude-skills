Stack Pack — SvelteKit + Svelte 5

When meta-govern detects: package.json includes @sveltejs/kit (with svelte >=5). Detection is dependency-based, never file-based: sv 0.16 puts the adapter + compilerOptions in vite.config.ts via the sveltekit() plugin and ships NO svelte.config.js, so never gate SvelteKit detection on that file (project-detection.mjs keys off @sveltejs/kit → stack.isSvelteKit / IF_STACK_SVELTEKIT).

# Layout reference

Default architecture pattern: framework-native + feature-first (see architecture-patterns.html). SvelteKit's file-based router lives in src/routes/; reusable components and stores live under src/lib/. Backend code (Convex, server-only utilities) lives in sibling top-level dirs, never under src/routes/.

Typical tree:

src/
  routes/                 ← file-based router; +page.svelte / +layout.svelte / +page.server.ts
    (authed)/             ← route group for auth-gated pages
      library/
        +page.svelte
        +page.ts          ← client+server load fn (universal)
    auth/
      +page.svelte
  lib/
    components/           ← reusable Svelte components (.svelte)
    stores/               ← cross-component state (.svelte.ts or runes-based stores)
    api/                  ← typed wrappers around backend clients
  app.html                ← root HTML shell
worker/                   ← stand-alone Cloudflare Worker (if used); NOT inside src/routes/
convex/                   ← Convex backend (if used)

# Path-scoped rules to install

In addition to the 9 core rules, install the Svelte-shaped ui-components rule — render from templates/rules/ui-components.svelte.md.tpl (selected automatically when IF_STACK_SVELTEKIT), NOT the React-shaped default. The React glob src/lib/**/*.{ts,tsx,jsx} matches no .svelte file, so shipping it leaves a silently dead rule (recurring friction — see lessons-log.html 2026-06-20).

  • ui-components.md (paths: src/lib/**/*.svelte, src/routes/**/*.svelte, src/lib/**/*.svelte.ts, src/**/*.css, messages/*.json):
    • User-facing strings through Paraglide: import * as m from '$lib/paraglide/messages', read as m.key(); add every key to BOTH locale files under messages/. No literal text in markup, no locale === 'fr' ? … : … ternaries.
    • Runes idioms: $state (local), $derived (computed), $effect (side effects), $props(). Derive with $derived; never mirror a prop into local state. No Svelte 4 idioms (export let, $:), no React patterns (useEffect/useState).
    • Design tokens only (tokens stylesheet + Tailwind @theme); no inline hex/rgba. Glass/motion restrained; honor prefers-reduced-motion.
    • Accessibility: accessible names, alt text, focus-visible, semantic headings; touch targets ≥ 44px.
    • In-app navigation: <a href="/route"> with SvelteKit preloading, or goto() from $app/navigation; locale-aware links via localizeHref() from $lib/paraglide/runtime. Don't reach into window.location for internal links.
    • When embedding untrusted content (user-uploaded HTML, third-party widgets) use <iframe sandbox="allow-scripts">. The sandbox attribute strips same-origin privileges; do not add allow-same-origin casually.

# Tooling stack

  • TypeScript strict mode (tsconfig.json extends ./.svelte-kit/tsconfig.json)
  • Svelte 5 with runes enabled (default in v5)
  • svelte-check for type checking (svelte-kit sync && svelte-check)
  • Vitest for unit tests; configure in vite.config.ts so it shares the SvelteKit Vite instance
  • Tailwind 3-4 with design tokens in tailwind.config.js
  • Husky 9 for pre-commit (size-guard + quality:check:staged)
  • Adapter: @sveltejs/adapter-vercel for Vercel deploys; @sveltejs/adapter-cloudflare for CF Pages; @sveltejs/adapter-node for self-host

# Load-function semantics — when SSR matters

SvelteKit gives you three flavors of data loading. Pick the one that matches the data:

  • +page.ts (universal) — runs on the server during SSR, then again in the browser on navigation. Use for public, cacheable data with no secrets in scope.
  • +page.server.ts (server-only) — only ever runs on the server. Use when the load needs DB credentials, server-only env vars, or you're rendering response headers/cookies.
  • No load fn — the page is fully client-rendered. Best for projects where all data goes through a reactive client (Convex, Firestore) and SSR provides no value.

For Convex-backed projects, the standard pattern is no load fn: pages mount, the Convex client subscribes, reactive queries hydrate the UI. Save server-load functions for traditional REST/SQL data.

# Tests

// src/lib/components/__tests__/UploadForm.test.ts
import { render, screen } from '@testing-library/svelte';
import UploadForm from '../UploadForm.svelte';

test('shows the file input', () => {
  render(UploadForm);
  expect(screen.getByLabelText(/upload html/i)).toBeInTheDocument();
});

Forbidden:

  • container.querySelector — use @testing-library/svelte queries
  • .toMatchSnapshot() on Svelte component output — brittle
  • Asserting on $state values directly — assert through the rendered DOM

# Validate command

{
  "scripts": {
    "dev": "vite dev",
    "build": "vite build",
    "preview": "vite preview",
    "check": "svelte-kit sync && svelte-check --tsconfig ./tsconfig.json",
    "test": "vitest run",
    "test:watch": "vitest",
    "validate": "npm run check && npm run test && npm run size-guard && npm run quality:check",
    "validate:fast": "npm run check && npm run test",
    "quality:check": "node .claude/scripts/quality-checks/index.mjs",
    "quality:check:staged": "node .claude/scripts/quality-checks/index.mjs --scope staged --fail-level high",
    "size-guard": "node .claude/scripts/file-size-growth-guard.mjs"
  }
}

Lint gates must not lint vendored governance assets. sv add wires eslint + prettier to scan the whole tree, including the meta-govern payload (.claude/** hooks with intentional empty catches, docs/** 50+ HTML + JS assets, src/lib/paraglide/** generated runtime). Left as-is, a freshly bootstrapped project fails its own bun run validate/lint. The bootstrap therefore augments .prettierignore and inserts an eslint global-ignores entry for .claude/**, docs/**, archive/**, src/lib/paraglide/** — every artifact the scaffold installs passes the gates the same scaffold installs (echo of the 2026-06-16 file-size-guard lesson). The bootstrap also merges quality:check, size-guard, test, validate, validate:fast into package.json add-if-missing, so the scripts CLAUDE.md points at actually exist.

# SvelteKit-app + Cloudflare Worker (split-deploy pattern)

When the project pairs a SvelteKit app on one origin with a separate Cloudflare Worker on another (e.g., a sandboxed view domain), keep them in the same repo but in separate top-level dirs:

src/                    ← SvelteKit app
worker/
  src/
    index.ts            ← Worker entry; reads R2, injects CSP, handles 404
  wrangler.toml         ← Worker config (separate from the app's vite.config.ts)
  package.json          ← optional, only if Worker has its own deps

Reasons to keep them split:

  • The Worker is the trust boundary for untrusted content. Code that touches user-uploaded HTML must not import anything from src/ (cookies, auth helpers, app routes).
  • wrangler dev and vite dev run on different ports and shouldn't share config.
  • Deployment pipelines are independent: SvelteKit ships to Vercel/CF Pages; Worker ships via wrangler deploy.

CLAUDE.md should call out the split with a path-scoped rule (worker/**/*.ts) noting the Worker has no access to app cookies and runs on a separate origin.

# Common gotchas

  • Svelte 5 components written in Svelte 4 idioms (export let prop, $: blocks) still work but cost legibility; in new files prefer $props() + runes.
  • +page.server.ts data is serialized over the wire — non-serializable values (functions, classes, Maps) silently break.
  • The app directory ($app/...) is virtual; don't try to import from node_modules/@sveltejs/kit/... directly.
  • File names matter: +page.svelte, +layout.svelte, +page.server.ts, +server.ts, +error.svelte. SvelteKit's router is filename-driven.
  • Tailwind dark-mode: pin the strategy in tailwind.config.js (darkMode: 'class' is the modern default).
