Per-Project Baseline (template)

This file describes the canonical content of a project's .claude/skills/govern-claude/references/baseline.md — the artifact that the project-level govern-claude skill diffs against to detect drift.

Master skill meta-govern writes this file during BOOTSTRAP into each project at: <project>/.claude/skills/govern-claude/references/baseline.md

It uses the template at ~/.claude/skills/meta-govern/templates/governance-baseline.md.tpl rendered with project-specific variables.

# What baseline.md contains

The per-project baseline is the expected inventory for THIS project at THIS palier:

  1. Skills expected (5 core + palier-specific extras)
  2. Agents expected (4 core + palier-specific extras)
  3. Hooks expected (5 core + palier-specific extras)
  4. Path-scoped rules expected
  5. Scripts expected
  6. Source-of-truth docs expected (paths)
  7. package.json scripts expected
  8. .husky/pre-commit content expected
  9. .gitignore additions expected
  10. Drift detection rules
  11. Evolution path (palier triggers)

# How project-level govern-claude uses it

project's govern-claude skill
   ↓
reads baseline.md
   ↓
walks .claude/ directory
   ↓
diffs actual vs expected
   ↓
reports findings (orphans, missing, oversized, defensive scaffolding)
   ↓
proposes diffs (NEVER applies)

# How meta-govern updates it

When meta-govern runs MIGRATE (palier promotion or version bump):

  1. Read current baseline.md
  2. Compute diff vs new expected baseline (per palier + version)
  3. Apply additions, mark removals as deprecated
  4. Update .claude/.meta-govern.json palier
  5. Bump baseline.md version stamp at top

When meta-govern runs EVOLVE (self-update):

  1. New version means new expected baseline shape
  2. Existing projects' baseline.md become candidates for MIGRATE

# Cross-references

  • Template: ~/.claude/skills/meta-govern/templates/governance-baseline.md.tpl
  • Project govern-claude: <project>/.claude/skills/govern-claude/SKILL.md
  • Master scripts: ~/.claude/skills/meta-govern/scripts/{audit-project,migrate-project}.mjs

# Why per-project baseline exists

Without a project-level baseline, govern-claude has nothing to diff against. The baseline encodes the user's standards AT THIS POINT IN TIME. As meta-govern evolves, baselines update; old projects become MIGRATE candidates.

This separation (baseline = local snapshot; meta-govern = global standard) prevents:

  • Drift bleeding across projects (each has its own baseline)
  • Forcing all projects to the absolute latest (older projects evolve at user pace)
  • Lost institutional memory (the baseline is timestamped + versioned)

# Drift detection scope

The project-level govern-claude skill (using its baseline) detects drift in:

  • .claude/skills/, .claude/agents/, .claude/hooks/, .claude/rules/, .claude/scripts/
  • CLAUDE.md, AGENTS.md (if dual-runtime)
  • package.json validate scripts
  • .husky/pre-commit
  • Source-of-truth doc presence (NOT content — content evolves freely)

It does NOT detect drift in:

  • Application source code (src/, app/)
  • Tests (tests/)
  • Build outputs

# Lessons-log integration

When a lesson surfaces during AUDIT:

  1. Project's govern-claude/references/session-lessons.md records it (project-specific)
  2. If the lesson is generic → bubble up to ~/.claude/skills/meta-govern/references/lessons-log.html
  3. If accumulated → meta-govern EVOLVE updates the canonical baseline template
  4. Next MIGRATE picks up the change

This is the self-healing feedback loop in action.
