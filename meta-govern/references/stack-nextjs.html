# Path-scoped rules to install

In addition to the 8 core rules:

  • ui-components.md (paths: src/app/**/*.tsx, src/features/**/*.tsx, src/shared/ui/**):
    • Tailwind tokens only (no inline hex/rgba)
    • dark: variants where dark mode applies
    • Accessibility: aria-label, alt text, semantic HTML, keyboard navigation
    • Touch targets 44px minimum (36px for dense controls)
    • Use Next <Link> for in-app navigation; <a href> only for external URLs
  • server-client-boundary.md (paths: src/app/**/*.tsx, src/app/**/route.ts, src/server/**/*.ts) — see templates/rules/server-client-boundary.md.tpl:
    • 'use client' at the smallest interactive boundary, never at the page top
    • route.ts parses, validates, calls a service, responds — no DB calls, no auth logic, no transformations
    • Durable backend logic in src/server/<area>/
    • Server Components by default; client components are exceptions, not the norm
  • data-layer.md (paths: src/server/**/*.ts):
    • Repositories per aggregate root (when DDD score ≥10)
    • Boundary schemas (Zod) at every server-action / route-handler entry
    • No business logic in repositories — they read/write only

# Source-of-truth doc structure

Three canonical docs (same as React+Vite):

  1. docs/<project>-spec.md — FUNC-XX, RA-XX, VAL-XX
  2. docs/data-model.md — schema, contracts (server entities, client DTOs)
  3. docs/composants/catalogue-composants.md — C-XX components

# Tooling stack

  • Next.js 15+ with App Router (Server Components default)
  • TypeScript strict mode
  • ESLint 9 flat config with @next/eslint-plugin-next
  • Prettier 3+
  • Vitest 4 for unit/component (preferred) OR Jest 30 if existing
  • Playwright for e2e (lives in tests/e2e/)
  • Tailwind 3-4 with design tokens
  • Husky 9 + lint-staged 16 for pre-commit
  • Zod for boundary schemas

# Tests

// src/features/<feature>/__tests__/<feature>.test.tsx
import { render, screen } from '@testing-library/react';
import Page from '../page';

it('renders the dashboard heading', async () => {
  render(await Page());
  expect(screen.getByRole('heading', { level: 1 })).toBeInTheDocument();
});

Forbidden:

  • container.querySelector — use Testing Library queries
  • .toMatchSnapshot() — brittle
  • DB mocks at the component level — mock at the service layer

# Common gotchas

  • Route handler bloat: route.ts accumulating DB calls + auth + validation + transformations = 200-line hotspot. Extract to src/server/<area>/.
  • 'use client' cascade: marking a parent client makes the entire subtree client. Mark the smallest interactive leaf instead.
  • Server Components reading from localStorage / window: server-side execution has no DOM. Move to client component or pass as prop.
  • next/image size: not setting width/height blocks LCP. Always specify or use fill with a sized parent.
  • Cache mistakes: fetch() in Server Components caches by default; unstable_noStore() or cache: 'no-store' for dynamic data.
  • ISR / revalidate: forgetting export const revalidate = 60 on a page that needs freshness → stale forever.
  • useEffect + setState for derived data: a quality-checks anti-pattern. Compute during render, or use a selector.
  • File size > 300 lines: caught by file-size check.

# Archetype defaults (see project-archetypes.html)

  • Archetype A (prototype): rare for Next.js — usually overkill. Consider React+Vite first.
  • Archetype B (internal dashboard): Next.js with src/app/(app)/ route group + minimal marketing.
  • Archetype C (production SaaS): default Next.js home. Marketing route group + app route group + API route handlers + shared schemas.
  • Archetype D (larger system): Next.js as one app inside a monorepo (apps/web/ or apps/admin/); see stack-monorepo.html.
