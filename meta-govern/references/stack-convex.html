Stack Pack — Convex Backend

When meta-govern detects: package.json includes convex OR convex/ directory exists with _generated/.

# Layout reference

Default architecture pattern: framework-native + feature-first on the frontend (per architecture-patterns.html); the convex/ directory follows the domain-folder layout (see Convex schema discipline), schema in convex/schema.ts.

# Path-scoped rules to install

In addition to the 8 core rules:

  • data-layer.md (paths: convex/**/*.ts, src/**/queries/**, src/**/mutations/**):
    • Convex hooks only (no fetch direct in components)
    • Bilingual columns denormalized (e.g., nameFr, nameEn not name: { fr, en })
    • Money: integer cents, CAD only, Intl.NumberFormat('fr-CA') on client
    • Errors: throw new ConvexError({ code, message }) with code added to translations
    • Repositories one-per-table (NOT generic IRepository<T>)
    • Mutations must invalidate query keys

# Convex schema discipline

  • Schema in convex/schema.ts
  • One file per table or cohesive sub-domain, organized per the domain-folder layout below
  • Generated services in convex/_generated/ (DO NOT EDIT)
  • Use v.string(), v.number(), v.id("table"), v.array(...), v.object({...})
  • Index fields used in queries

# Domain-folder layout (readability)

The root of convex/ keeps ONLY the files Convex mandates there: schema.ts, http.ts, auth.config.ts, convex.config.ts, crons.ts (if any). Everything else lives in folders: lib/ (shared helpers), one folder per domain, migrations/. Function references become api.<domain>.<file>.<fn>. The flat "one file per table at root" layout does not scale and buries the mandated files.

convex/
  schema.ts · http.ts · auth.config.ts · convex.config.ts   ← Convex-mandated root
  lib/          shared helpers (auth guard, domain math)
  <domain>/     one file per table or cohesive sub-domain
  migrations/   backfills, one-shot data moves

Concrete instance: personal-budget-app docs/specs/2026-07-01-convex-migration-mcp-agent-design.html §2A (finance/, shopping/, settings/, agent/, ai/, mcp/).

Basename rule — single-dot only. Convex function discovery ignores multi-dot basenames (confirmed via CONVEX_VERBOSE=1): taxonomies.ExpenseTypes.ts silently exports nothing. The dot-notation extraction pattern from file-size-budget does NOT apply under convex/ — extract oversized function files as single-dot camelCase siblings (expenseAndDebtTypes.ts). Import-only helpers (expenses.shared.ts) and *.test.ts are safe (not discovered). Cross-ref: file-size-budget.md Convex addendum (personal-budget-app DEFERRED-005, 2026-07-02).

# Migration discipline

  • Use @convex-dev/migrations for breaking schema changes
  • Pattern: widen → migrate → narrow
  • Test migrations on a snapshot copy
  • Parity is not counts+sums+hard-FK. A backfill parity report must include EVERY ref-like field — including typed v.string() fields holding foreign keys — with its resolution rate against the target table's keys. Hard-FK checks on v.id(...) fields alone let string refs stay 100% dangling while every counter reads green (personal-budget-app 2026-07: expenses.category/budgets.type still held unmapped Firestore IDs, 721/721 dangling, parity declared PASS; caught only by owner visual QA, fixed in project commit 1e0197e).
  • A deliberate parity improvement is documented, never silent. When the migrated code is intentionally MORE correct than legacy (spec-authoritative fix), record it as such in the parity report and the spec delta — neither ship it silently nor "fix" it back to legacy behavior (personal-budget-app RA-04/RA-06).

  • Use Convex test harness (@convex-dev/test) for backend tests

# Mutation payload casts

A type cast (as never, as any, as unknown as X) on the args of a useMutation/useAction handle masks a client↔validator payload mismatch that Convex rejects at RUNTIME (ArgumentValidationError). The compiler error the cast silences IS the contract violation report — fix the payload or the validator, never cast (personal-budget-app 2026-07: 36 as never casts masked 3 CRITICAL payload mismatches while 213 mocked tests stayed green; the failures only surfaced at execution against real validators).

  • Mocked component tests do not exercise validators — green mocks prove nothing about the payload contract. Pair them with real-boundary tests (convex-test) for every mutation the UI calls.
  • Deterministic enforcement: audit-project.mjs flags casts bound to a useMutation/useAction handle call (area convex-mutation-casts, HIGH, v1.11.0) — TS exhaustiveness as never, test mocks and comments are structurally excluded (callee-bound heuristic).

# Validate command

{
  "scripts": {
    "convex:dev": "convex dev",
    "convex:codegen": "convex codegen",
    "typecheck": "tsc -b --noEmit && tsc -p convex --noEmit",
    "validate": "bun run typecheck && bun run lint && bun run test && bun run build && bun run quality:check && bun run convex:codegen"
  }
}

convex:codegen alone does not typecheck convex/ — it validates references, not function bodies, and the app's root tsconfig typically excludes convex/. Include tsc -p convex --noEmit in typecheck from bootstrap so a bad function body fails the gate at commit, not at deploy (gap observed on personal-budget-app, fixed in dca6763).

# Common gotchas

  • Don't query inside loops (N+1 problem) — use indexed queries or denormalize
  • Watch for OCC (Optimistic Concurrency Conflict) on hot rows — handle retries
  • Aggregate counts denormalized via convex-dev-aggregate component
  • Subscriptions are reactive — careful with high-frequency updates
  • Money is integer cents (avoid floats; use Intl.NumberFormat('fr-CA') for display). Note: this is the Brillance-Décor default, not universal — some projects run float dollars by recorded ADR (e.g. personal-budget-app). Read the project's data-model doc before imposing cents.

# Convex frugality contract (function calls, bandwidth, egress)

Convex bills by usage. On a usage-billed backend, frugality is a DESIGN contract, not a late optimization — the path of least friction (testing against the deployment, returning raw rows, adding a convenient cron) bills the quota directly. Born from a real quota-exhaustion incident (workstation, 2026) and codified during the personal-budget-app migration design (§3.8 + AC-25). Apply to every Convex project at design time and at review time:

GuardrailRule
Zero cron without a cost-justified designNo crons.ts entry ships without its own design section justifying the function-call cost
Tests never hit a deploymentThe whole test suite runs on convex-test (in-memory). Deployments serve only one-shot integration probes / smoke tests, never test loops. A test file importing a deployment URL or ConvexHttpClient is a blocking review defect
Indexed queries onlywithIndex everywhere; a full table scan is a blocking review defect
Bounded readsServer-side limit (default 50, max 200) on list-shaped tools/queries exposed to LLMs or exports; aggregates computed server-side — never ship raw rows for client-side reduction
Single subscription per tableOne useQuery per table via a façade (DataContext-style); "skip" when unauthenticated
Frugal streamingAgent/LLM stream deltas debounced; thread context bounded (no full-history re-injection)
Batched backfillsBackfill/migration batches ≤ 500 docs per mutation
Usage surveillanceRead + archive the Convex usage dashboard (function calls, bandwidth) at each phase-exit gate; run convex-performance-audit in final scans
