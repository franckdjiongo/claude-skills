Evolution Roadmap — Paliers 0-6

Source: adaptation of Brillance Décor's evolution-roadmap.html palier system, generalized for any project.

# What's a palier?

A palier is an evolutionary stage of a project's Claude Code setup. Higher paliers add capabilities; lower paliers stay simple. Promotion is trigger-driven — never preemptive.

# Indicators (measured by analyze-project.mjs)

For each project, meta-govern measures:

  • LOC (lines of code)
  • FUNC IDs (count of FUNC-XX references in spec)
  • C-XX components (count in catalog)
  • Test files
  • Devs (1 = solo, ≥2 = multi-dev)
  • Backend: absent / in-progress / mature
  • CI: absent / GitHub Actions / GitLab / other
  • DEFERRED entries in backlog
  • Multi-runtime (Codex + Claude.ai dual): no / yes
  • Archetype (A=prototype | B=internal-dashboard | C=production-saas | D=larger-system) — see project-archetypes.html
  • Architecture pattern (framework-native-feature-first | feature-sliced | vertical-slice | modular-monolith | clean-hexagonal | package-monorepo) — see architecture-patterns.html

# The paliers

# Palier 0 — Greenfield

State: No .claude/ directory yet. Maybe a package.json, maybe nothing.

Indicators:

  • LOC < 100
  • No CLAUDE.md
  • No .claude/

Trigger to promote: User invokes BOOTSTRAP.

# Palier 1 — Initial bootstrap

State: Standard meta-govern bootstrap installed. Project is ready for serious work.

Installed:

  • CLAUDE.md (≤120 lines)
  • .claude/settings.json (3 hooks)
  • .claude/rules/ (8 path-scoped rules)
  • .claude/skills/ (5 core: brainstorm, write-plan, execute-plan, quality-gate, govern-claude)
  • .claude/agents/ (6: implementer, ui-implementer, spec-reviewer, code-quality-reviewer, persona-simulator, codebase-reality-check)
  • .claude/hooks/ (5: track-workflow, enforce-workflow, precompact-handoff, postcompact-reinject, session-start-env-check)
  • .claude/scripts/ (file-size-growth-guard + quality-checks suite)
  • 3 source-of-truth docs (spec, data-model, catalog)
  • package.json validate scripts
  • .husky/pre-commit
  • docs/backlog-deferred.md

Trigger to promote to Palier 2:

  • ≥30 FUNC IDs in spec
  • OR ≥10 C-XX components
  • OR live users / production deployment
  • OR ≥30 components + tests

# Palier 2 — Spec maturity

State: Project has substantial scope. Spec coverage and QA matter.

Adds:

  • spec-tracer skill (generates docs/traceability/trace-global.md)
  • qa-plan skill (generates manual QA docs)
  • (Optional) update-manifest skill if data model has machine-readable manifest

Trigger to promote to Palier 3:

  • 2+ devs
  • OR worktree workflow needed (parallel feature branches)
  • OR spec violations recur

# Palier 3 — Multi-dev

State: Multiple developers. Coordination matters.

Adds:

  • spec-reviewer agent (split from generic reviewer)
  • subagent-plan-edit-guard hook (scoped to implementer agents)
  • setup-worktree.mjs script
  • agent-dispatch-preflight.mjs hook (file-size warnings on dispatch)
  • Worktree workflow documentation

Trigger to promote to Palier 4:

  • PR opened on remote (GitHub/GitLab)
  • OR CI requested

# Palier 4 — CI ready

State: Project ships through CI; release notes matter.

Adds:

  • .github/workflows/ (or GitLab CI) for: lint, typecheck, test, build, quality:check
  • release-notes skill
  • Coverage gate in validate
  • Branch protection rules (documented; not auto-applied)

Trigger to promote to Palier 5:

  • Codex / Claude.ai dual-runtime needed (e.g., for non-MCP integrations)
  • OR project served from multiple Claude surfaces

# Palier 5 — Dual-runtime

State: Project supported by Claude Code AND Codex (or another runtime).

Adds:

  • .codex/ adapter
  • AGENTS.md (Codex equivalent of CLAUDE.md)
  • .agents/ shared core (mirrors of skills/rules accessible to both runtimes)
  • sync-claude-mirrors.mjs script
  • govern-runtime-sync skill

Trigger to promote to Palier 6:

  • 30+ DEFERRED entries in backlog
  • OR backlog overhead >1h/week

# Palier 6 — Backlog automation

State: Mature project with substantial accumulated debt.

Adds:

  • next-deferred-id.mjs script (allocates DEFERRED-XXX IDs)
  • backlog-cleanup skill (or scheduled task)
  • Auto-categorization of deferred items by severity / area
  • Periodic backlog review cadence (monthly)

Beyond Palier 6: Custom evolution. meta-govern proposes per-project; user decides.

# Promotion is not free

Each palier adds standing-context cost. Promote only when triggers are met.

Palier Cumulative artifacts Approx. standing-context overhead
0 0 0 tokens
1 5 skills + 4 agents + 5 hooks + 8 rules + CLAUDE.md ~3-4K tokens (CLAUDE.md + skill metadata + rule headers)
2 +2 skills +100 tokens
3 +1 agent + 2 hooks + worktree +200 tokens
4 +1 skill + CI files +50 tokens
5 +adapter + sync script + AGENTS.md mirror +500 tokens
6 +1 script +50 tokens

The user's CLAUDE.md still budget is ≤120 lines regardless of palier.

# Demotion / pruning

Sometimes a palier feature isn't paying off. meta-govern AUDIT detects:

  • Skills with 0 invocations in 90 days → propose retirement
  • Hooks that never fired → propose deletion
  • Rules with no matching paths → propose deletion or path correction
  • Agents not invoked in 90 days → propose retirement

Demotion is opt-in. The user reviews proposals.

# Per-project palier file

Each project tracks its palier in .claude/.meta-govern.json:

{
  "metaGovernVersion": "1.2.0",
  "palier": 1,
  "archetype": "B",
  "architecturePattern": "framework-native-feature-first",
  "lastAudit": "2026-05-06",
  "lastBootstrap": "2026-05-06",
  "stack": "react-vite-convex",
  "dddScore": 6,
  "indicators": {
    "loc": 3450,
    "funcIds": 28,
    "components": 18,
    "tests": 12,
    "devs": 1,
    "backend": "in-progress",
    "ci": "absent",
    "deferred": 4,
    "multiRuntime": false
  }
}

analyze-project.mjs reads & writes this file.

# When meta-govern bumps major version

If a meta-govern major version requires re-scaffolding (e.g., template structure changed), every project's metaGovernVersion is now stale → MIGRATE candidates.

The migration is incremental:

  1. Read project's current palier
  2. Compute the diff for that palier between old and new meta-govern version
  3. Apply step-by-step
  4. Update metaGovernVersion in .meta-govern.json

NEVER bulk-migrate across paliers. Promote by trigger; migrate by version.

# Trigger checklists summary

0 → 1: User invokes BOOTSTRAP. Always-promote-on-request.
1 → 2: ≥30 FUNC IDs OR ≥10 C-XX OR live users.
2 → 3: 2+ devs OR worktree needed.
3 → 4: PR on remote OR CI requested.
4 → 5: Dual-runtime needed.
5 → 6: 30+ DEFERRED entries.

If a trigger is partially met (e.g., 25 FUNC IDs out of 30), AUDIT recommends "stay at palier N; promote in ~2 weeks" rather than promoting prematurely.
