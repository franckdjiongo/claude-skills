Model & Effort Defaults — Selection Guide

Sources: Claude 5 Workflow Playbook (2026-07-01, QA-verified distillation of Anthropic's prompting guides + the Sonnet 5 System Card); previously effort-level-decision-framework-claude-code-opus-4-7-sonnet-4-6.md. Critical for any session that uses Claude Code as of July 2026.

This file's name is deliberately model-agnostic: at each model release, update the Current lineup section and the tier tables — never the filename. (The pre-v1.7.0 name was opus-4-7-defaults.html; renaming it at every release was the debt this layout retires.)

# Current lineup (versioned)

Lineup as of 2026-07 (Claude 5 family release):

Model API id Claude Code alias Role in this doctrine Availability
Claude Sonnet 5 claude-sonnet-5 sonnet Workhorse default at high; preferred on untrusted-content surfaces GA
Claude Opus 4.8 claude-opus-4-8 opus Hardest pure reasoning; xhigh escalation; fallback tier GA
Claude Fable 5 / Mythos 5 claude-fable-5 — Hardest unsolved problems only — never structural doctrine Time-boxed: included in Max 20x until 2026-07-07 only, then API-billed → retired from this workflow

The durable anchor is Sonnet 5 + Opus 4.8. Models with bounded availability (Fable 5) get dated notes, never scaffolding: no send-to-user tooling, no refusal-fallback wiring, no multi-day-timeout guidance enters project templates on their account.

# The 3 + 1 heuristics

  1. Default to high on Sonnet 5 for Claude Code. xhigh is the ceiling for the hardest work, not the session default — Sonnet 5 high already carries what Sonnet 4.6 called max.
  2. Pick the model first, the effort second. Sonnet 5 first for coding and agentic work; escalate to Opus 4.8 when reasoning depth (not code volume) is the bottleneck. Plan-then-build sessions: plan mode on the stronger model (opusplan-style alias where your Claude Code build exposes it).
  3. max is per-subproblem rescue, not session default.
  4. Effort names don't carry equal depth across model versions. Sonnet 5 medium ≈ Sonnet 4.6 high; Sonnet 5 high ≈ Sonnet 4.6 max. Benchmark by observed thinking length, never by the level's name.

# Default tier per task

MOST CODING (features, refactors, tests-with-logic, reviews)
└─ Sonnet 5 + high ─────────────── the workhorse; near-Opus at Sonnet pricing

HARDEST MULTI-FILE REFACTOR / DEBUG / ARCHITECTURE
└─ Sonnet 5 + xhigh or Opus 4.8 + xhigh

HARDEST PURE REASONING / AMBIGUOUS DESIGN
└─ Opus 4.8 + xhigh ────────────── also the fallback tier

UNTRUSTED CONTENT (web pages, PR diffs, third-party tool output)
└─ Sonnet 5 ────────────────────── most injection-resistant, at any effort

TESTS / DOCS / UTILITY SCRIPTS
└─ Sonnet 5 + medium ───────────── ≈ old Sonnet 4.6 high; rarely limiting

CLASSIFICATION / FORMATTING / SIMPLE RENAMES
└─ Sonnet 5 + low ──────────────── strictly scoped; raise effort if shallow

STUCK PROBLEM (one turn)
└─ /effort max for ONE turn ────── then drop back; max ≠ session default

# Per-task playbook

Task type Model + effort
Architectural planning Plan mode on Opus 4.8 (opusplan-style alias where available)
Greenfield single-file Sonnet 5 + high
Multi-file refactor Sonnet 5 + xhigh; Opus 4.8 + xhigh on repeated failure
Intermittent debugging Sonnet 5 + xhigh; escalate to Opus 4.8 when the bug resists
Long-horizon agentic Sonnet 5 + xhigh + auto mode
Code review Sonnet 5 + high with a coverage-not-filtering prompt (Opus 4.8 + xhigh for architecture review)
Untrusted-content agents (browser, PR triage, web research) Sonnet 5, any effort — see security surface
Tests Sonnet 5 + medium
Documentation Sonnet 5 + medium
Utility scripts Sonnet 5 + low or medium
Classification Sonnet 5 + low
Migration Sonnet 5 + xhigh; Opus 4.8 for the risk analysis
Failing / looping Bump one effort level (don't add scaffolding); switch model on second failure

# Effort recalibration across model versions

Effort levels are model-relative. Reusing yesterday's level names on today's models silently changes both cost and depth.

Sonnet 5 level ≈ Sonnet 4.6 equivalent Consequence
medium high Yesterday's "high" workloads now run fine at medium — free cost cut
high max A session pinned to xhigh out of habit pays old-max prices on every turn
  • Benchmark by observed thinking length, not the level name. The names are UI labels; the depth behind them moves at each release.
  • Sonnet 5 respects low strictly. At low/medium it scopes work to exactly what was asked. Good for latency and cost — but a documented under-thinking risk when a nominally mechanical task turns moderately complex. The fix is raising effort, never prompting around shallow reasoning.
  • Session default = high. xhigh is reserved for the hardest coding/agentic work; max is a one-turn rescue.

# Model choice by security surface

Model selection has a second axis besides task difficulty: what the agent reads. Any agent consuming untrusted content — web pages, PR diffs from external contributors, third-party tool output that could carry injected instructions — should prefer Sonnet 5 regardless of intelligence needs.

  • Coding-environment prompt-injection attack success: 0.31% on Sonnet 5 (with thinking) vs 7.03% on Opus 4.8 (Sonnet 5 System Card, p.62–65).
  • Browser-use prompt-injection attack success: 0.93% on Sonnet 5 vs 31.5% on Opus 4.8 and 50.7% on Sonnet 4.6 (p.63).

Corollary — over-refusal on security-shaped prompts: Sonnet 5 refuses more legitimate dual-use security work than Sonnet 4.6 (91.55% success on benign dual-use tasks vs 97.33%). Security-adjacent prompts (pentest tooling, recon scripts, auth hardening) need explicit authorization framing — state the engagement, the ownership of the target, and the defensive intent in the prompt itself.

# Per-subagent effort frontmatter

Subagents do NOT inherit session effort by default — set explicitly in frontmatter:

---
name: lint-fix
model: sonnet
effort: low
---
Subagent role Effort
Mechanical (lint-fix, git-publisher, CLI caller) low
Bulk implementer (per-task TDD-light) medium
Reviewer / researcher high
Planner / architect xhigh

On Sonnet 5 these named levels each carry roughly one tier more depth than they did on Sonnet 4.6 (see recalibration). Keep the role→level mapping, but watch low agents: Sonnet 5's strict scoping means a "mechanical" agent whose task quietly grows complex under-thinks silently — recalibrate by observed thinking, not tradition.

# In-session diagnostic matrix

When something feels off, diagnose before raising effort:

Signal Diagnosis Action
Spec ambiguous Need plan first Switch to plan mode on the stronger model
Solution too shallow Underpowered Bump effort one level (on Sonnet 5, never prompt around shallow reasoning)
Solution overengineered Overpowered Drop one level
Long sessions getting expensive Later-turn thinking grows at high+ effort /clear more often or drop one effort level
Subagent under-tools Low effort / thinking-off reduces tool reach on Sonnet 5 Add positive prompt example + raise effort, not "MUST use X"
Reviewer reports trivial issues Defensive scaffolding in prompt Rewrite prompt: explicit AC + scope + severity matrix
Reviewer reports too FEW findings Severity-filter language obeyed literally (recall trap) Coverage-not-filtering: report everything with confidence + severity; filter downstream
Failing repeatedly Probably underpowered One-turn /effort max, then drop back; switch model on second failure
Code subtly wrong but spec satisfied Under-thinking on multi-step work at low/medium Bump to high or xhigh

# Anti-patterns (Claude 4.7+ / Claude 5 family)

  • Defaulting a long session to max — ~2x the spend for ~3-4 percentage points of quality.
  • Pinning xhigh out of habit — on Sonnet 5, high already carries old-max depth; xhigh-by-default pays a premium the task rarely needs.
  • Adding prompt scaffolding to compensate for shallow reasoning → "raise effort, not scaffolding."
  • Migrating old prompts unchanged — severity-filter language ("don't nitpick", "only critical issues") is obeyed literally and you lose review recall. See the coverage-not-filtering row in anti-pattern-catalog.html.
  • Letting mechanical subagents inherit session effort → set effort: explicitly in their frontmatter.
  • Trusting low on moderately complex work — Sonnet 5 scopes strictly; the failure is silent (literal spec satisfied, downstream broken).
  • Setting thinking: {budget_tokens: N} — returns 400 on all current models (Opus 4.7+, Sonnet 5, Fable 5/Mythos 5). Adaptive thinking + effort is the only mode.
  • Setting non-default temperature/top_p/top_k on Sonnet 5 — returns 400. Steer tone/variety via system-prompt instructions instead.
  • Prefilling the last assistant turn — removed since Claude 4.6 (400). Move the constraint into the system/user turn or use structured outputs.

# Effort precedence

ENV var ($CLAUDE_CODE_EFFORT_LEVEL)
    ↓
Skill or subagent frontmatter (effort: ...)
    ↓
Session-level /effort
    ↓
settings.json effortLevel
    ↓
Model default

To pin an effort level permanently for a machine, set in ~/.claude/settings.json:

{"effortLevel": "high"}

high is the recommended pin on the current lineup; reserve xhigh for per-session or per-subagent escalation.

# Non-Claude-Code deployments

Model aliases (opus, sonnet) auto-resolve only in Claude Code. On Bedrock / Vertex / Foundry and in direct API code, pin explicit model strings (claude-sonnet-5, claude-opus-4-8) and confirm per-deployment config.

# When xhigh pays for itself

xhigh pays back when retries are expensive — xhigh's 2× token cost is lower than high's 1.25× expected runs × debugging overhead for tasks where:

  • Acceptance criteria are partially ambiguous
  • Multiple files need to coordinate
  • Edge cases matter (state machines, transactions, refunds)
  • Migration risk is real

xhigh does NOT pay when:

  • Task is mechanical / unambiguous
  • Concurrent Max-plan sessions where weekly quota constrains you
  • You're already inside Plan Mode (the model already concentrates effort there; max is the trap)
  • Sonnet 5 at high already delivers old-max depth — verify the task actually outruns it before escalating

# CLAUDE.md skeleton block (BOOTSTRAP injects)

## Default model + effort
- Default: sonnet (Sonnet 5) at high — workhorse for most coding; near-Opus quality at Sonnet pricing, gentler on quota.
- Escalate: sonnet (Sonnet 5) or opus (Opus 4.8) at xhigh for the hardest multi-file refactor, debugging, architecture; opus for the hardest pure reasoning.
- Untrusted content (web pages, PR diffs, third-party tool output): prefer sonnet — most prompt-injection-resistant tier.
- Plan then build: plan mode on the stronger model (`opusplan`-style alias where available).
- Drop: `/effort low` for classification, formatting, simple renames. Sonnet 5 respects low strictly — raise effort if reasoning turns shallow; don't prompt around it.
- Rescue: `/effort max` for ONE turn on stuck problems, then drop back.
- Effort names don't carry equal depth across model versions (Sonnet 5 medium ≈ Sonnet 4.6 high; high ≈ old max) — benchmark by observed thinking length.
- Subagents declare their own effort. Mechanical → low. Implementer → medium. Reviewer → high. Planner → xhigh.
- Spawn multiple subagents in the same turn when fanning out across items or files.
- State explicit intent, constraints, acceptance criteria, file paths. Don't generalize silently.

This block is the user's contract with the current lineup (Sonnet 5 + Opus 4.8). meta-govern ensures it appears in every project's CLAUDE.md — the identical text lives in templates/CLAUDE.md.tpl, and four-tier-architecture.html carries a compressed one-liner of it; the three surfaces stay in lockstep.
