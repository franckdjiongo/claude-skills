The Four-Tier Architecture — Progressive Context Disclosure

Source: synthesis of Progressive Context Disclosure for Claude Code on Windows.md, Claude Code Architecture Research.md. Confirmed by both production projects.

# The four tiers

Standing context degrades quality at scale. Even with 1M context, accuracy drops from 93% (256K) to 76% (1M). Practitioners observe ~2% effectiveness loss per 100K tokens added. The four-tier hierarchy is how the user keeps standing context small while shipping comprehensive standards.

Tier 1 ──── CLAUDE.md ────────────────────────── ≤120 lines, always loaded
            project identity + invariants + pointers + commands
            ↓
Tier 2 ──── .claude/rules/*.md ──────────────── path-scoped, ~200 tokens loaded only when matching files touched
            file-type / directory conventions
            ↓
Tier 3 ──── Skills ─────────────────────────── ~50 tokens metadata, body ~5K when triggered
            multi-step workflows, domain knowledge
            ↓
Tier 4 ──── Hooks ─────────────────────────── zero context cost
            deterministic enforcement

# Tier 1: CLAUDE.md

# Budget: ≤120 lines

Claude Code Architecture Research.md recommends ≤120 (stricter than the 150 in Progressive Context Disclosure doc). Take the stricter number.

# What belongs

  • Project identity (1-2 lines)
  • Source of truth pointers (3 docs: spec, data model, component catalog)
  • Stack summary (1-2 lines: framework, runtime, package manager)
  • Always-on rules (5-10 bullets, NON-DEFENSIVE language)
  • Commands (table format: npm run validate, npm run quality:check)
  • Path-scoped routing (docs/architecture/** → load references/architecture-strategy.md)
  • Compaction recovery (After Compaction section — the only post-compact survivor)
  • Notes durables + pointeur d'état (.claude/.meta-govern.json pour palier/version/déclencheurs) — jamais l'état lui-même

# What does NOT belong

  • Long style guides → move to .claude/rules/*.md
  • Architecture explanations → move to docs/architecture/* and add a pointer
  • File-type procedures → move to .claude/rules/*.md
  • Review checklists → move to a skill (e.g., quality-gate)
  • Migration playbooks → move to a skill (e.g., bun-migration)
  • @filename imports → use declarative pointers (UI behavior: docs/document-ui-ux-v1.md)
  • Defensive scaffolding ("MUST", "double-check before returning") → DELETE
  • État volatil (palier, version meta-govern, compte de constats/tests, statut de migration, « backend vivant = X », « aujourd'hui/currently ») → vit dans .claude/.meta-govern.json / HANDOFF.md / docs vivants ; le standing context pointe. Test du rot : « cette phrase peut-elle devenir fausse sans qu'on édite CE fichier ? »

# Example skeleton

# <Project Name> — CLAUDE.md

## Projet
<one paragraph: what this is, who it serves>

## Source de vérité
- `docs/<project>-spec.md` — FUNC-XX, RA-XX, VAL-XX
- `docs/data-model.md` — schema, contracts
- `docs/composants/catalogue-composants.md` — C-XX

## Stack
React 19, TypeScript 5.8, Vite 6, Convex, R2. Runtime: Bun.

## Commands
| Goal | Command |
|---|---|
| dev | `bun run dev` |
| validate | `bun run validate` |
| quality | `bun run quality:check` |

## Règles non-négociables
- Toute string utilisateur via `LocalizedString` + `useContent()`
- File-size cap 300 lignes; dot-notation extraction sinon
- Hooks Convex uniquement (pas de `fetch` direct)
- Money: integer cents, CAD
- Reviews: foreground only

## Routing path-scoped
- `components/**/*.tsx` → `.claude/rules/ui-components.md`
- `convex/**/*.ts` → `.claude/rules/data-layer.md`
- `tests/**/*.test.*` → `.claude/rules/testing.md`

## Default model + effort
Sonnet 5 high is the workhorse default. Sonnet 5/Opus 4.8 xhigh for the hardest work; Opus 4.8 for hardest pure reasoning + fallback. Plan mode on the stronger model for plan-then-build.

## Après compaction
Re-read this file. If `HANDOFF.md` exists, read it. Resume work.

## État gouvernance
Palier, version, déclencheurs : voir .claude/.meta-govern.json (ne pas dupliquer).

# Tier 2: .claude/rules/*.md

# Budget: ≤50 lines per file, paths: frontmatter mandatory

Loaded only when matching files are in the active context. Zero standing-context cost when files outside the path are touched.

# Frontmatter contract

---
description: <one-line, what convention this enforces>
paths:
  - components/**/*.tsx
  - components/**/*.module.css
---

# What belongs

Path-conditional conventions. Examples:

  • components/**/*.tsx → use LocalizedString, no hardcoded strings, no <a href> for in-app navigation
  • convex/**/*.ts → repository per table, ConvexError codes, mutations invalidate queries
  • tests/**/*.test.* → no container.querySelector, no snapshot tests, async assertions

# What does NOT belong

  • Always-on rules → CLAUDE.md
  • Multi-step workflows → skill
  • Anything that needs deterministic enforcement → hook

# Tier 3: Skills

# Budget: ~50 token metadata always loaded; ~5K body on trigger

Each skill is ~/.claude/skills/<name>/SKILL.md (user-level) or .claude/skills/<name>/SKILL.md (project-level).

# Internal three-level disclosure

  1. Frontmatter (always loaded): name, description (with WHEN-to-use triggers).
  2. Body (loaded on trigger): workflow steps, decision points, examples.
  3. References (loaded on demand): references/*.md files; subfolders for templates, scripts, examples.

# What belongs

  • Multi-step repeatable workflows (brainstorm → plan → execute)
  • Domain knowledge (DDD reference, Cloudflare Workers patterns)
  • MCP enhancement (orchestrating Notion + Linear together)

# Trigger phrasing in description

Per Doc 4 research: aggressive language markers in frontmatter description push activation from ~50% to 80-84%. In frontmatter, use markers; in body, don't.

Description shape: [What it does] + [When to use it] + [Trigger phrases users would say] + [Distinct from X].

# Tier 4: Hooks

# Budget: Zero context cost (run outside LLM)

Located in .claude/hooks/*.mjs (project) or ~/.claude/hooks/ (none in current setup, all project-level).

# 22 hook lifecycle events

By category:

  • Session: SessionStart, SessionEnd
  • Conversation: UserPromptSubmit, Stop
  • Tool: PreToolUse, PostToolUse, PostToolUseFailure
  • Subagent: SubagentStart, SubagentStop
  • Context: PreCompact, PostCompact, InstructionsLoaded, ConfigChange
  • Infrastructure: WorktreeCreated, WorktreeDestroyed, NotificationDisplay, ElicitationRequested

# Default hook set (BOOTSTRAP creates these)

Event Hook Purpose
SessionStart session-start-env-check.mjs Verify node, git, bun (Apple Silicon PATH)
PostToolUse Edit/Write/MultiEdit/Bash track-workflow.mjs Record edits + validate runs
Stop enforce-workflow.mjs Block if validate not run since last edit
PreCompact precompact-handoff.mjs Write HANDOFF.md
PostCompact postcompact-reinject.mjs Re-inject critical discipline

# What belongs in hooks

  • 100% deterministic enforcement (no skill activation roulette)
  • Format-on-edit
  • Block-destructive (rm -rf in /, secrets in commits, console.log in production)
  • Test-gate before completion
  • Env self-check

# Cost-efficient hook design

  • Prefer denials with short reasons over dumping logs into context
  • Write details to a file, return a one-line pointer
  • Use context: fork for verbose operations
  • Apple Silicon: explicit PATH, no nvm dependency, silent startup

# When tiers conflict

If a rule could fit two tiers, pick the lower-cost one that achieves required reliability.

Rule Lower-cost option When the higher-cost option wins
"Use LocalizedString" Path-scoped rule If hardcoded strings keep slipping through → add a hook
"Run TDD" Skill If devs skip TDD → add a Stop hook that blocks completion if no test edited
"Format on save" Hook Always hook (deterministic)
"Bounded context = environment" CLAUDE.md (identity) If too much context, move to references/ddd-application.md and pointer

# CLAUDE.md compaction survival

Critical: Only CLAUDE.md and PostCompact hook output survive /compact. Everything else (rules, skill bodies, subagent context) is cleared.

This means:

  • Compaction-critical rules live in CLAUDE.md
  • Compaction-recovery instructions live in CLAUDE.md ## Après compaction section
  • Long-running plan execution discipline lives in postcompact-reinject.mjs

# Validation checklist (BOOTSTRAP / AUDIT)

If any of these fail → AUDIT mode emits findings.

# Palier 5: AGENTS.md mirror

Dual-runtime projects (Claude Code + Codex) at palier 5 mirror CLAUDE.md as AGENTS.md so Codex picks up the same standing context. The mirror is a thin pointer, not a duplicate — it references CLAUDE.md and lists Codex-specific deltas (typically just the build/test commands and the safety section). Drift between the two is detected by the palier-5 sync-claude-mirrors.mjs script.

Le miroir hérite de la doctrine durable-only : AGENTS.md ne porte jamais d'état (palier, version, compte de tests, statut de migration) — il pointe vers CLAUDE.md et .claude/.meta-govern.json comme CLAUDE.md le fait. Le seul delta légitime est Codex-spécifique et durable (commandes build/test, section safety).

Single-runtime Claude-only projects (palier ≤4) do not need AGENTS.md. See evolution-roadmap.html palier 5 for promotion triggers.
