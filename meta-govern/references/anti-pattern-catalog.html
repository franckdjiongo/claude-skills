# Claude Code anti-patterns

# CLAUDE.md anti-patterns

Anti-pattern Symptom Fix
Bloat (>120 lines) Standing context cost; instruction adherence degrades Move file-type rules to .claude/rules/, move workflows to skills, keep only identity + pointers + invariants
@filename imports Embeds full file every session start Replace with declarative pointer: Spec: docs/spec.md
Defensive scaffolding "MUST", "ALWAYS", "double-check before returning", "n'oublie pas" Delete. Current Claude models (4.7+/5) follow literally; performance drops — over-prescriptive bodies actively degrade output on the newest models. Aggressive markers ALLOWED only in skill descriptions (frontmatter) for activation.
Architecture explanations inline Long sections explaining why we chose X Move to docs/architecture/ and add a router pointer
File-type procedures inline "When editing components, use LocalizedString..." Move to .claude/rules/ui-components.md with paths: frontmatter
Routing without paths: Path-scoped rule loaded globally Add paths: frontmatter to the rule
Migration playbooks inline Long step-by-step migrations Move to a skill (e.g., bun-migration)
Stale references Pointer to a doc that no longer exists AUDIT detects; meta-govern proposes diff
État volatil dans le standing context CLAUDE.md/AGENTS.md contient palier, version meta-govern, « ~416 constats », « N tests », « backend vivant = X », « Convex pas encore de schéma », « aujourd'hui/currently » — divergent du réel au premier changement Déplacer l'état vers sa source canonique (.claude/.meta-govern.json, HANDOFF.md, docs vivants, le code) ; laisser un pointeur durable. Test du rot : « cette phrase peut-elle devenir fausse sans éditer ce fichier ? ». AUDIT détecte (stale-state HIGH si divergent, state-duplication LOW si présent)

Anti-pattern Symptom Fix
Missing paths: frontmatter Rule loaded globally always Add paths: glob list
Negative-only ("Never use X") Vague; doesn't tell what to do Add positive: "Never X. Instead use Y."

# Skills anti-patterns

Anti-pattern Symptom Fix
Vague description Skill auto-triggers <50% of relevant queries Rewrite: WHAT + WHEN + 5+ trigger phrases
README.md inside skill folder Forbidden by Anthropic Delete; move content into SKILL.md or references/
Folder name not kebab-case Skill silently invalid Rename to kebab-case
name: differs from folder Routing surprises Match name: to folder name
"claude" or "anthropic" in name Reserved keyword Rename
XML angle brackets in frontmatter Prompt injection vector Remove
Body >5000 words Slow loading; reduced trigger reliability Move detail to references/, keep body lean
disable-model-invocation: false on side-effect skills Skill auto-runs and deploys/mutates state Set to true for any skill with side effects
Subagents listed without effort: Subagent inherits session xhigh Add explicit effort: to subagent frontmatter

# Hooks anti-patterns

Anti-pattern Symptom Fix
Missing /opt/homebrew/bin PATH node/git/bun not found on Apple Silicon Set explicit PATH in hook script
nvm dependency Breaks if user opens session without nvm init Use #!/usr/bin/env node with absolute PATH or homebrew-installed node
Profile output (echo in .zshrc) Corrupts JSON hook responses Profile must be silent at startup
Interactive prompts Hooks have no TTY; hangs forever All input via stdin/stdout JSON
Skipping hooks (--no-verify) "Just bypass this once" → cumulative drift Treat as production infrastructure; fix the root cause
Verbose stdout in hooks Floods context Write details to file; return 1-line pointer
Background reviewers via hooks Same as subagent: 0-byte Foreground hooks only for review-style work
Untested guard / hook A hook that throws exits 0 and blocks nothing — the guard silently does not exist Ship the hook's simulation/test in the same commit, exercising block AND allow paths (detected by audit-project.mjs area hook-tests)
Guard contournable (angle mort Bash) A PreToolUse guard scoped to Edit/Write protects a path, but the same write reaches the target through a Bash redirect / tee / sed -i / heredoc — the guard never sees it, so the invariant holds for one vector only Pair the Edit-scoped guard with a Bash companion (bash-write-guard.mjs) that parses the command via detectWriteTargets; deny the protected vectors, shadow-log src/** until BASH_WRITE_GUARD_ENFORCE=1 promotes them (area bash-write-guard, v1.15.0)
Suite verte vacuous — les tests tournent, pas qu'ils attrapent A green suite proves the tests ran, not that they would fail on a real regression: asserts on props not behavior, mocks that never touch the boundary, a guard test with no block-path case Every guard/rule test carries a POSITIVE case (blocks the forbidden) AND a NEGATIVE case (lets the legitimate through); above ~1000 cases, mutation-test the highest-value guards — flip the condition, confirm a test goes red (see governance-cadence.html mutation-testing ritual)

# API / harness anti-patterns (Claude 5 family)

Anti-pattern Symptom Fix
thinking: {budget_tokens: N} (manual extended thinking) 400 error on all current models (Opus 4.7+, Sonnet 5, Fable 5/Mythos 5) Adaptive thinking + the effort parameter is the only mode
Non-default temperature/top_p/top_k on Sonnet 5 400 error (new constraint for Sonnet-class models) Steer tone/variety via system-prompt instructions; for design variety, have the model propose options before building
Prefilled last assistant turn 400 error since Claude 4.6 models Move the constraint into the system/user turn, use structured outputs, or XML output tags
Severity-filtered review prompts ("only significant issues", "don't nitpick") Recall trap on Sonnet 5: the model investigates fully and finds the bugs, but obeys the filter and doesn't report them — precision rises, recall silently falls Coverage-not-filtering: the finding stage reports everything with confidence + severity attached; filtering/ranking happens downstream. Single-pass filters use a concrete bar ("could cause incorrect behavior, a test failure, or a misleading result"), never qualitative words. Wired into templates/agents/spec-reviewer.md.tpl + code-quality-reviewer.md.tpl

# Strategic anti-patterns

Anti-pattern Symptom Fix
DDD-Lite Tactical patterns (aggregates, repos) without bounded contexts/UL Strategic first. Skip tactical until score ≥10.
Big Ball of Mud BC One BC handling everything Split by ubiquitous language; each BC has its own glossary
Shared database across BCs Coupling, deployment lockstep Each BC owns its persistence; integrate via events/contracts
Confused subdomain classification Treating supporting like core or vice versa Re-score on Khononov axes (differentiation × complexity)
Bounded context = microservice always Premature deployment fragmentation All microservices are BCs, not all BCs are microservices

# Tactical anti-patterns

Anti-pattern Symptom Fix
Anemic Domain Model Entities are setter-bags; logic in services Move invariants into entity methods; reject public setters
God Aggregate Aggregate >100ms load Split aggregate; reference other roots by ID only
Generic Repository IRepository<T> Repository becomes leaky CRUD One repository per AGGREGATE ROOT; methods named in ubiquitous language
Leaky Repository Returns IQueryable / raw rows Return fully-valid aggregates only
Infrastructure leaking into domain EF Core types in domain entities Domain has zero ORM dependency; mapper-as-ACL at boundary
Primitive obsession string customerEmail instead of Email value object Promote frequently-used primitives to value objects
Multiple aggregates per transaction Contention, deadlocks, unclear ownership One aggregate per transaction. Use eventual consistency between aggregates.
Public setters on aggregates Outside code mutates state, bypasses invariants Private setters, public methods named in UL
Event sprawl Events fired for every state change, no architectural value Events for domain transitions, not CRUD
Double-write without outbox Save aggregate + publish event in 2 transactions → eventual inconsistency Outbox pattern: insert outbox row in same DB transaction; separate dispatcher publishes
Contract-masking type cast Mocked tests stay green while the backend validator rejects the real payload — as never/as any on mutation args silences the compiler error that WAS the contract-violation report Fix the payload or the validator, never cast; pair mocked tests with real-boundary tests (see stack-convex.html#mutation-payload-casts; detected by audit-project.mjs area convex-mutation-casts)
Parity port-miss A rewrite/migration carries only the AC-named branches; legacy early-returns/clamps/error paths silently dropped Inventory the legacy source branch-by-branch (git show main:<file>) and map each branch to the port (reviewer structural checklist (d); implementer Step 1)

# 10 code-review signals of anemic drift (Doc 2)

Bake these into your code-quality-reviewer agent or quality-gate script:

  1. Public setters on aggregate roots
  2. Primitives where value objects are documented in glossary
  3. Validation logic in controllers (should be in domain)
  4. Resource-named commands (PUT /orders vs domain commands)
  5. Application services holding invariants
  6. Mutable collections returned from aggregates
  7. Present-tense events (UpdateOrder vs OrderShipped)
  8. Property-only tests (no behavior assertions)
  9. ORM types (DbContext, Entity attributes) in domain layer
  10. Lazy-loaded cross-aggregate navigation properties

# Detection in scripts

scripts/audit-project.mjs runs automated detection:

  • Claude-Code anti-patterns: file size, defensive scaffolding regex, @-imports, missing paths:, vague descriptions, README in skill folders, etc.
  • DDD anti-patterns (when DDD score ≥10): public setter detection, IRepository regex, ORM types in domain folders, primitive params on commands, etc.
  • Convex data-contract anti-patterns (gated isConvex): crons without a cost-justified marker, tests hitting a real deployment (area convex-frugality, v1.7.1); type casts on useMutation/useAction args (area convex-mutation-casts, HIGH, callee-bound heuristic, v1.11.0).
  • Env drift (gated isVite, only when .env.local exists): VITE_* keys read bare by src/ via import.meta.env.* but missing from .env.local (area env-parity, MEDIUM, with a declarable optionalEnvKeys escape hatch in docs/docs-map.json, v1.11.0).
  • Hook / guard test discipline: a project-authored .claude/hooks/*.mjs (outside the canonical set) with no associated simulation/test (area hook-tests, HIGH, v1.12.0) — a broken guard fails open silently.
  • Guard-vector parity (v1.15.0): an Edit/Write-scoped protection with no Bash companion, so a redirect/tee/sed -i slips past (area bash-write-guard, HIGH when a protected path has an unguarded write vector).
  • Runtime parity (v1.15.0): a governance/workflow guard present for one runtime but not its twin — a hook wired in settings.json with no Codex mirror, or vice-versa (area runtime-parity, MEDIUM).
  • CI policy (v1.15.0): the absence of server-side CI. When .claude/.meta-govern.json declares ciPolicy: 'local-compensation', the missing CI is presented as an OPTION, not a finding; the local Stop gate + predeploy-check.mjs are the documented compensation (area ci-policy).

Output: severity-tagged findings with file:line references.

# When to surface

  • BOOTSTRAP: After scaffold, run anti-pattern scan on the templates that were just installed (sanity check).
  • AUDIT: Always.
  • MIGRATE: Always (anti-patterns may emerge during migration).
  • EVOLVE: Self-audit detects anti-patterns in meta-govern itself.

# Always-grow this catalog

When a new anti-pattern is observed:

  1. Append to lessons-log.html
  2. Add a row to the relevant table here
  3. Update audit-project.mjs with a new check (if scriptable)
  4. Bump meta-govern minor version

The catalog is a living document. Stale entries also rot — periodically prune patterns that no longer apply (e.g., when Claude Code adds a feature that obsoletes a workaround).
