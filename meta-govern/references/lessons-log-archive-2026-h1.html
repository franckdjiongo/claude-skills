# 2026-05-06 — Both projects — User repeats bootstrapping ritual every project

Project: N/A (cross-project observation)
Severity: HIGH
Type: WORKFLOW
Recurrence: Observed across Temps Chantier + Brillance Décor + implied 8+ other projects

# What happened

Each new project started, the user manually:

  • Created CLAUDE.md
  • Set up .claude/skills/ with brainstorm, write-plan, execute-plan, quality-gate, govern-claude
  • Created .claude/agents/ with implementer + reviewer
  • Wired hooks for track-workflow, enforce-workflow, precompact-handoff
  • Wrote 8 path-scoped rules
  • Set up package.json validate scripts
  • Wrote source-of-truth docs (spec, data-model, catalog)
  • Decided per-project on DDD vs Transaction Script

The same setup work, repeated. The user's words: "à chaque nouveau projet, j'ai l'impression de toujours recommencer les mêmes choses".

# Root cause

No global master skill encapsulating the BOOTSTRAP. govern-claude was project-level only.

# Action taken

# Lesson generalized

When you would catch yourself building the same primitive (skill / agent / hook / rule) for the third project in a row, that's the signal to extract it into meta-govern's templates instead.

# 2026-05-06 — Cross-project — Defensive scaffolding accumulated from Opus 4.6 era

Project: Likely both
Severity: MEDIUM
Type: MODEL
Recurrence: 1st (corrective)

# What happened

Opus 4.6 generalized helpfully when prompts said "MUST", "ALWAYS", "double-check before returning". Opus 4.7 follows literally and underperforms. Defensive scaffolding inherited from earlier projects becomes anti-pattern on Opus 4.7.

# Root cause

Model behavior change between 4.6 and 4.7.

# Action taken

# Lesson generalized

Aggressive language markers ("MUST", "ALWAYS", "CRITICAL") are TARGETING instructions in frontmatter — they push skill activation from 50% to 80-84%. They are LITERAL CONSTRAINTS in skill bodies / CLAUDE.md / rules — Opus 4.7 obeys them in unhelpful ways. Use markers in frontmatter; don't use them in bodies.

# 2026-05-06 — Cross-project — Skills auto-trigger 50-84%; critical rules need hooks

Project: N/A (architectural)
Severity: HIGH
Type: ARCHITECTURE
Recurrence: 1st (foundational)

# What happened

Practitioners report Claude Code skill auto-invocation activates only 50-84% of the time. For critical project rules, this is unacceptable.

# Root cause

Skills are probabilistic; their description-based triggering competes with all enabled skills.

# Action taken

# Lesson generalized

For critical project rules, do not trust skill auto-invocation. Use hooks. Skills give the probabilistic layer; hooks give the deterministic layer.

# 2026-05-07 — Cross-project — Architecture-pattern + archetype were missing dimensions

Project: N/A (research-driven)
Severity: HIGH
Type: ARCHITECTURE
Recurrence: 1st (research-anticipated; codified before observation)

# What happened

v1.0.0 and v1.1.0 picked stack (React+Vite, Power Platform, Convex) and palier (0-6) per project, but never asked how the source tree should be laid out nor what kind of project this is. BOOTSTRAP defaulted to whatever the stack pack scaffolded, with no machine-readable record of intent. AUDIT could not detect layout drift because there was no "this is the chosen pattern" record.

# Root cause

The 2026 research synthesis (LLM-friendly project architecture for AI coding agents in 2026.md) makes explicit a dimension that was implicit in the user's two production projects: agents read repositories better when layout is framework-native + feature-first, and when the kind of project (prototype / internal tool / SaaS / larger system) is recorded so palier-1 install can match the kind. The user-imposed scope kept this Claude-Code-only — Codex coexistence already handled by palier 5; no Copilot/OpenCode integration.

# Action taken

# Lesson generalized

Two orthogonal dimensions belong in .claude/.meta-govern.json from day one: archetype (the project's kind) and architecture pattern (the layout strategy). Stack pack picks tools; archetype picks scaffold depth; pattern picks tree shape. Without all three recorded, AUDIT cannot detect drift and MIGRATE cannot reason about consistency.

# 2026-05-07 — meta-govern self — Master sub-agent dispatch was unreachable in practice

Project: meta-govern itself (v1.2.0 → v1.2.1 patch)
Severity: HIGH
Type: WORKFLOW
Recurrence: 1st (caught by user during v1.2.0 EVOLVE run, before recurrence)

# What happened

During the v1.2.0 EVOLVE run, SKILL.md's EVOLVE Mode 4 step 3 said "Spawn evolution-orchestrator". The parent (Claude) silently bypassed the dispatch and authored the evolution plan inline, until the user asked "why did you not spawn evolution-orchestrator as the skill says?". Investigation showed three reinforcing failures:

  1. The 9 master sub-agents at ~/.claude/skills/meta-govern/agents/ were never symlinked into ~/.claude/agents/. Claude Code's Agent tool only loads from ~/.claude/agents/ and project-level .claude/agents/, so Agent({subagent_type: "evolution-orchestrator"}) would have failed with "subagent type not found". The dispatch path was unreachable from the start.
  2. SKILL.md said "Optionally delegate verbose work to sub-agents" (line 53). Opus 4.7 follows instructions literally; "Optionally" is a linguistic affordance to skip.
  3. Mode steps used the verb "Spawn" without the matching tool-call contract Agent({subagent_type: ...}). With no exact invocation, the model picked the lowest-friction interpretation: synthesize the role inline.

# Root cause

The skill was authored assuming sub-agents at ~/.claude/skills/<skill>/agents/ were dispatchable; they aren't (Claude Code only loads from ~/.claude/agents/). Combined with permissive language and missing invocation contracts, the silent-skip path was easier than the correct path.

# Action taken

# Lesson generalized

A skill that "spawns sub-agents" must (1) ship those sub-agents at the path Claude Code's Agent tool actually reads, (2) include the exact Agent({subagent_type: ...}) invocation contract in every dispatch point, and (3) verify dispatchability in self-audit. Otherwise the silent-skip path becomes the default — the model rationalizes inline-authoring as "I have full context", and the orchestration protocol that gives outputs their auditability and reproducibility quietly evaporates.

# 2026-05-07 — env-variable-manager (Power Apps Code App) BOOTSTRAP — Template rendering didn't reflect architect skip decisions

Project: env-variable-manager (palier 0 → 1, archetype B, stack power-platform-react-vite, DDD score 2/16)
Severity: HIGH
Type: SCAFFOLDING
Recurrence: 1st

# What happened

BOOTSTRAP step 5 produced a working palier-1 install (29 templates + 14 additional steps, 0 errors), but coherence-validator caught two related rendering defects on the way out:

  1. Orphan Mustache tag in ui-components.md. Line 11 had a literal {{#IF_STACK_HAS_UI}} with no closing {{/IF_STACK_HAS_UI}}. The conditional body rendered correctly (because IF_STACK_HAS_UI=true) but the opening token leaked into the output verbatim. Future audits would have flagged this as a content artifact.
  2. baseline.md listed all standard palier-1 artifacts as expected, ignoring the architect's skip list. The architect's plan explicitly skipped persona-simulator agent, data-layer.md rule, quality-checks/ directory, .husky/pre-commit, and three quality:check* scripts. The rendered baseline.md still listed them under "Expected", which on day-1 govern-claude audit would have produced 4–6 false-positive missing-artifact findings. Two project-level skill bodies (brainstorm referencing persona-simulator, write-plan referencing data-layer.md) had the same issue.

# Root cause

  • The Mustache renderer in bootstrap-project.mjs apparently doesn't error on unbalanced section tags; it emits the opening token literally when there's no matching close. Neither the architect nor the scaffolder caught this because both work at a higher abstraction (file lists + verbatim writes), not at the rendered-content level.
  • Skill/agent/rule template bodies are authored against the FULL palier-1 corpus and don't accept skip flags. The scaffolder writes them verbatim. The architect's flags block (IF_STACK_HAS_UI, etc.) is consumed but IF_PERSONA_SIMULATOR_INSTALLED / IF_RULE_DATA_LAYER_INSTALLED flags don't exist in the template-renderer vocabulary, so artifacts that were skipped at the plan layer still appear in baseline expectations and skill prose.

# Action taken (project-local, this BOOTSTRAP only)

# Lesson generalized

Bootstrap rendering must respect the architect's skip list end-to-end, not just at the file-creation layer. Two template-renderer hardening tasks for a future meta-govern patch:

  1. Reject unbalanced Mustache section tags. bootstrap-project.mjs should error on {{#FOO}} without a matching {{/FOO}} rather than emit the literal token. A 1-line strict-mode flag on the renderer would catch this at scaffold time.
  2. Pass the skip set as boolean flags into every template that names palier-1 artifacts. Templates like baseline.md.tpl, brainstorm/SKILL.md.tpl, write-plan/SKILL.md.tpl should consume IF_AGENT_PERSONA_SIMULATOR_INSTALLED, IF_RULE_DATA_LAYER_INSTALLED, etc., from the architect's plan. The current architecture pushes the burden of "filter for what was skipped" downstream; it should be applied at render time.

Until those hardening tasks land, every BOOTSTRAP run on a stack-pack that uses skips (Archetype B, TRANSACTION_SCRIPT DDD, etc.) will produce the same drift — a post-render fix-up pass after coherence-validator is the workaround.

# 2026-05-09 — htmlshare BOOTSTRAP — SvelteKit gap, scaffolder defaults still React-shaped, audit-script SoT detector blind spot

# Trigger

BOOTSTRAP run on a personal-scale Convex + SvelteKit + Cloudflare R2/Worker + Vercel + Resend project (archetype B, DDD score 3 → Transaction Script). meta-govern v1.2.1 has no stack-sveltekit.html reference and the React-flavored frontend templates leaked into rule and agent bodies even when variable substitution targeted Svelte.

# Observed drift (caught and patched inline)

  • .claude/rules/ui-components.md template paths: was src/lib/components/**/*.{ts,tsx,jsx} + pages/**/*.{ts,tsx,jsx} — dead globs in a SvelteKit project. The rule never auto-loaded on .svelte files. Body referenced useEffect, useMemo, <Link>, useContent(). Rewrote globs to src/routes/**/*.svelte, src/lib/**/*.svelte, src/lib/**/*.svelte.ts and the body to Svelte 5 runes ($state, $derived, $effect) plus the in-app preview <iframe sandbox="allow-scripts"> guidance.
  • .claude/rules/spec-protocol.md template paths: listed generic template defaults (docs/data-model.md, docs/composants/catalogue-composants.md) instead of the project-actual docs/<project>-data-model.md + docs/<project>-catalog.md. Rule did not auto-load on the real SoT files. Substitution only targeted *-spec.md.
  • .claude/rules/clean-code.md and .claude/rules/file-size-budget.md templates ship a single paths: glob (src/**/*.{ts,svelte}) — missing convex/**/*.ts. Convex code was not covered by either rule despite CLAUDE.md's routing table claiming both. Added convex/**/*.ts manually.
  • .claude/rules/data-layer.md body referenced docs/data-model.md (no project prefix) — drift from the real docs/htmlshare-data-model.md. Rule body link drifted while frontmatter paths: was correct.
  • .claude/agents/ui-implementer.md description string still said "Builds React/UI components"; Step 4 referenced useEffect/setState/useSyncedState/Parent.tsx. Substitution only happens via {{VAR}} tokens; React idioms in body prose are unsubstituted text. Rewrote inline.
  • CLAUDE.md rendered with a 35-line HTML comment block containing the literal template variable map ("htmlshare — Human-readable project name", etc.). The renderer leaked the comment-bracketed template metadata into the final file. Stripped manually.
  • CLAUDE.md ## Après compaction section restated the trust-boundary callout already in ## Règles non-négociables — claude-config-style.md "one concept, one place" violation. De-duplicated.

# Audit-script blind spot

scripts/lib/project-detection.mjs:221-229 candidate-path lists for dataModelPath and catalogPath cover docs/data-model.md, docs/lexique-donnees-dataverse.md, docs/composants/catalogue-composants.md, docs/components/catalog.md — but NOT docs/<project>-data-model.md or docs/<project>-catalog.md. Even though the SoT scaffolder uses the <project>- prefix as its standard pattern, the audit detector misses them and emits HIGH/MEDIUM false-positive findings. False positives erode signal — the audit then says "drift" when the project is fine.

# Action taken (project-local, this BOOTSTRAP only)

# Lesson generalized

Three EVOLVE candidates for a future meta-govern minor:

  1. Author references/stack-sveltekit.html. Cover: glob conventions for .svelte and .svelte.ts, Svelte 5 runes idioms ($state, $derived, $effect), the <iframe sandbox="allow-scripts"> pattern for embedding untrusted content, SvelteKit's load-function semantics (when to use +page.server.ts vs +page.ts), Vercel adapter pin, and the pattern for projects that pair a SvelteKit app with a separate Cloudflare Worker (worker code lives in worker/, not src/routes/). Until this exists, every SvelteKit project pays the same tax of post-render Svelte adaptation.

  2. Strip template-variable HTML comments at render time. The bootstrap renderer should skip leading HTML comment blocks of the form <!-- Template variables: ... --> when rendering CLAUDE.md / agent / skill templates. These are documentation for template authors, not content for the rendered file. Easiest fix: a single regex pass in template-renderer.mjs that strips <!--\s*Template variables:.*?--> blocks.

  3. Extend SoT-detection candidate paths. scripts/lib/project-detection.mjs:221-229 should glob docs/*-data-model.md and docs/*-catalog.md (or accept *-data-model.md / *-catalog.md filename patterns alongside the existing exact paths). The <project>- prefix pattern is already the SoT scaffolder's default; the audit detector should match what the scaffolder produces.

# Bonus observations

  • .claude/.meta-govern.json writes flat dddScore + dddDecision keys, but the architect's plan specified nested ddd: { score, decision }. Values are correct; shape diverges from architect intent. Schema-shape divergence is a v1.2.x cleanup candidate.
  • .claude/.meta-govern.json uses lastBootstrap key name; some validators expect bootstrappedAt. Date value is correct. Same kind of name-vs-value drift.
  • .claude/.meta-govern.json writes claudeMdLines once at scaffold time; after subsequent CLAUDE.md edits it goes stale. Either compute on demand or update on every meta-govern run.
  • enforce-workflow hook is wired to the Stop event in templates; the workflow-validator checklist names UserPromptSubmit / PreToolUse as expected events. The Stop event is functionally correct ("block end-of-turn") but the checklist should add Stop as an accepted event for enforce-workflow.
  • The 5 stack packs (stack-convex.html, stack-monorepo.html, stack-nextjs.html, stack-power-platform.html, stack-react-vite.html) cover most of what users actually ship to. Adding stack-sveltekit.html and stack-cloudflare-workers.md (for stand-alone Worker projects, distinct from Pages) would close the bulk of the gap.

Strips both pattern variants (<!-- Template variables: ... --> and <!-- Template variables (substituted at BOOTSTRAP): ... -->).
  • ✓ scripts/lib/project-detection.mjs:221-229 extended: docs/*-data-model.md and docs/*-catalog.md added as the FIRST candidate in each list (preferred over the legacy hardcoded paths). Existing exact-path candidates retained for backward compat.
  • ✓ SKILL.md "When to load which reference" table gained a stack-sveltekit.html row.
  • ⏸ version.json bump to 1.2.2 was BLOCKED by the harness (treated as agent self-modification). The 4 changes above are in place; the version.json bump + changelog entry need to be applied manually by the user. Until then, projects continue to record metaGovernVersion: "1.2.1", but the runtime code/doc improvements are active.
