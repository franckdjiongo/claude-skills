Opus 4.7 Defaults — Model & Effort Selection

Source: effort-level-decision-framework-claude-code-opus-4-7-sonnet-4-6.md. Critical for any session that uses Claude Code as of May 2026.

# The 3 + 1 heuristics

  1. Default to xhigh on Opus 4.7, high on Sonnet 4.6 for Claude Code.
  2. Pick the model first, the effort second. Use opusplan for any session with both planning and execution.
  3. max is per-subproblem rescue, not session default.
  4. low on Opus 4.7 ≈ medium on Opus 4.6 (Caitlin Colgrove, Hex CTO). Cost floor moved up.

# Default tier per task

DESIGN / DEBUG / REFACTOR / MIGRATE / PLUGIN AUTHOR
└─ Opus 4.7 + xhigh ────────────── default for serious work

WELL-SPECIFIED SINGLE-FILE FEATURE
└─ Sonnet 4.6 + high ──────────── faster, cheaper, sufficient

TESTS / DOCS / UTILITY SCRIPTS
└─ Sonnet 4.6 + medium ────────── over-thinking is wasted

CLASSIFICATION / FORMATTING / SIMPLE RENAMES
└─ Sonnet 4.6 + low ──────────── /effort low for the duration

PLAN-THEN-BUILD SESSIONS
└─ opusplan ──────────────────── auto-switches model

STUCK PROBLEM (one turn)
└─ /effort max for ONE turn ─── then drop back; max ≠ session default

# Per-task playbook

Task type Model + effort
Architectural planning opusplan
Greenfield single-file Sonnet 4.6 + high
Multi-file refactor Opus 4.7 + xhigh
Intermittent debugging Opus 4.7 + xhigh
Long-horizon agentic Opus 4.7 + xhigh + auto mode
Code review Sonnet 4.6 + high (Opus 4.7 + xhigh for architecture review)
Tests Sonnet 4.6 + medium
Documentation Sonnet 4.6 + medium
Utility scripts Sonnet 4.6 + low or medium
Classification Sonnet 4.6 + low
Plugin / connector opusplan
Migration Opus 4.7 + xhigh
Failing / looping Bump one level (don't add scaffolding)

# Per-subagent effort frontmatter

Subagents do NOT inherit session effort by default — set explicitly in frontmatter:

---
name: lint-fix
model: sonnet
effort: low
---
Subagent role Effort
Mechanical (lint-fix, git-publisher, CLI caller) low
Bulk implementer (per-task TDD-light) medium
Reviewer / researcher high
Planner / architect xhigh

# In-session diagnostic matrix

When something feels off, diagnose before raising effort:

Signal Diagnosis Action
Spec ambiguous Need plan first Switch to opusplan
Solution too shallow Underpowered Bump effort one level
Solution overengineered Overpowered Drop one level
Long sessions getting expensive Opus 4.7 thinks more on later turns at high effort /clear more often or drop to high
Subagent under-tools Default behavior on Opus 4.7 Add positive prompt example, not "MUST use X"
Reviewer reports trivial issues Defensive scaffolding in prompt Rewrite prompt: explicit AC + scope + severity matrix
Failing repeatedly Probably underpowered One-turn /effort max, then drop back
Code subtly wrong but spec satisfied Underpowered medium on multi-step Bump to high or xhigh

# Anti-patterns specific to Opus 4.7

  • Defaulting a long session to max — most "4.7 feels slow" reports trace here. ~2x the spend for ~3-4 percentage points of quality.
  • Adding prompt scaffolding to compensate for shallow reasoning → "raise effort, not scaffolding."
  • Migrating Opus 4.6 prompts unchanged — defensive language ("don't nitpick", "only critical issues") is now obeyed literally and you lose recall.
  • Letting mechanical subagents inherit session xhigh → set effort: low in their frontmatter.
  • Running medium effort on multi-step work — silent failure mode where Opus 4.7 satisfies the literal spec and breaks downstream.
  • Treating task-budgets-2026-03-13 as a Claude Code feature — it's Messages-API only.
  • Setting thinking: {budget_tokens: N} on Opus 4.7 — returns 400. Adaptive thinking is the only mode.

# Effort precedence

ENV var ($CLAUDE_CODE_EFFORT_LEVEL)
    ↓
Skill or subagent frontmatter (effort: ...)
    ↓
Session-level /effort
    ↓
settings.json effortLevel
    ↓
Model default

To pin xhigh permanently for a project, set in ~/.claude/settings.json:

{"effortLevel": "xhigh"}

# Bedrock / Vertex / Foundry deployments

The alias opus does NOT auto-resolve to Opus 4.7 on these deployments. Pin claude-opus-4-7 explicitly. Confirm in ~/.claude/settings.json or per-deployment config.

# When xhigh pays for itself

xhigh pays back when retries are expensive — xhigh's 2× token cost is lower than high's 1.25× expected runs × debugging overhead for tasks where:

  • Acceptance criteria are partially ambiguous
  • Multiple files need to coordinate
  • Edge cases matter (state machines, transactions, refunds)
  • Migration risk is real

xhigh does NOT pay when:

  • Task is mechanical / unambiguous
  • Concurrent Max-plan sessions where weekly quota constrains you
  • You're already inside Plan Mode (Opus already concentrates effort there; max is the trap)

# CLAUDE.md skeleton block (BOOTSTRAP injects)

## Default model + effort

- Default: opus (Opus 4.7) at xhigh for design, debug, refactor, migration, plugin work.
- Switch: sonnet (Sonnet 4.6) at high for tests, docs, single-file features, scripts.
- Plan then build: `opusplan` for any session with both phases.
- Drop: `/effort low` for classification, formatting, simple renames.
- Rescue: `/effort max` for ONE turn on stuck problems, then drop back.
- Subagents declare their own effort. Mechanical → low. Implementer → medium. Reviewer → high. Planner → xhigh.
- Spawn multiple subagents in the same turn when fanning out across items or files.
- State explicit intent, constraints, acceptance criteria, file paths. Don't generalize silently.

This block is the user's contract with Opus 4.7 and Sonnet 4.6. meta-govern ensures it appears in every project's CLAUDE.md.
