The Seven Primitives — Placement Framework

Source: synthesis of Claude Code Architecture Research.md, Progressive Context Disclosure for Claude Code on Windows.md, and 2 production projects.

# The seven primitives

Claude Code offers seven distinct primitives for shaping behavior. Each has a different cost, reliability, and scope. Misplacing a rule wastes tokens and produces drift.

# Primitive Standing context cost Reliability Best for
1 CLAUDE.md Highest (always loaded) 70-85% Identity, source-of-truth pointers, invariants, default model+effort, compaction recovery
2 .claude/rules/*.md Low (path-scoped via paths: frontmatter) 70-85% File-type / directory conventions, naming, accessibility, testing rules
3 Skills Metadata always loaded (~50 tokens), body lazy 50-84% auto-trigger Repeatable workflows, domain knowledge, multi-step processes
4 Subagents Zero main-thread cost; cost isolated to subagent 100% (when explicitly invoked) Verbose specialist work, code review, deep analysis, parallel dispatch
5 Hooks Zero context cost (run outside LLM) 100% deterministic Critical rules that MUST be enforced, env checks, format-on-edit, completion gates
6 MCP servers Tool-definition cost when active Tool-specific External system access (Notion, Vercel, GitHub, Convex)
7 Plugins Whatever they install Inherited Distribution, sharing

# Cost & reliability profile

Reliability:
   100% ████████████ Hooks
   100% ████████████ Subagents (explicit invocation)
   85%  █████████░░░ CLAUDE.md
   85%  █████████░░░ Path-scoped rules
   84%  ████████░░░░ Skills (best case, with markers + UPS hook)
   50%  █████░░░░░░░ Skills (worst case, no markers)

Standing-context cost (small project, indicative):
   2000+ tokens  CLAUDE.md (≤120 lines)
   200/file      .claude/rules/*.md (loaded only when path matches)
   50/skill      Skill metadata (always loaded if skill enabled)
   5K when active Skill body (loaded on trigger)
   0             Subagent (cost in its own context)
   0             Hooks (run as separate processes)
   variable      MCP tool definitions (only when MCP active)

# Placement decision matrix

For every rule, ask 5 questions to find the right primitive:

  1. Must it be followed 100% of the time? → Hook
  2. Is it path/file-type specific? → Rules file
  3. Is it always-on foundational identity / pointer? → CLAUDE.md
  4. Is it a repeatable multi-step workflow with domain knowledge? → Skill
  5. Does it require expensive reasoning that should not pollute the main context? → Subagent

If the rule fits multiple, pick the one that optimizes (cost × reliability × scope).

# Examples

  • "Block console.log from being committed" → Hook (100% deterministic, cheap, scoped to commits)
  • "Component files use LocalizedString" → Rules file with paths: ['components/**/*.tsx'] (path-specific)
  • "This project uses Convex + R2" → CLAUDE.md (identity, always loaded)
  • "Run brainstorm before writing a plan" → Skill (workflow, multi-step)
  • "Audit the entire .claude/ for drift" → Subagent (verbose, would flood main context)
  • "Log each session to a JSON file" → Hook
  • "Look up the latest Anthropic docs before answering" → MCP (external system)

# Anti-patterns by primitive

# CLAUDE.md anti-patterns

  • Long style guides, architecture explanations, file-type-specific procedures (use rules dir or skills instead)
  • @filename imports (embeds full file every session start; use declarative pointers instead)
  • Defensive scaffolding ("MUST", "ALWAYS", "double-check", "verify before returning") — Opus 4.7 follows these literally and underperforms
  • Over 150-200 instructions (HumanLayer research: adherence degrades uniformly past this)

# Rules anti-patterns

  • Missing paths: frontmatter (always loads → defeats path-scoping)
  • Files >50 lines (they pollute when loaded)
  • Negative-only rules ("Never use X") without providing the alternative

# Skills anti-patterns

  • Vague descriptions without trigger phrases (50% activation)
  • Variations of SKILL.md name (must be exact, case-sensitive)
  • README.md inside skill folder (forbidden)
  • "claude" or "anthropic" in skill name (reserved)
  • XML angle brackets in frontmatter (security: prompt injection vector)
  • Bodies >5000 words (degraded triggering, slow loading)
  • disable-model-invocation: false on side-effect skills (deploys, schema mutations)

# Subagents anti-patterns

  • Subagent-from-subagent dispatch (forbidden — 1-level only)
  • Plugin subagents declaring hooks, mcpServers, or permissionMode (silently ignored)
  • Running review agents in background (output may be 0-byte, fail silently)
  • Per-agent skills not declared in frontmatter (subagents don't auto-inherit skills)

# Hooks anti-patterns

  • Relying on interactive shell behavior or nvm initialization
  • Outputting to stdout from ~/.profile/~/.bashrc (breaks JSON hook responses)
  • Missing /opt/homebrew/bin on Apple Silicon (node, git, etc. not found)
  • Skipping --no-verify checks ("just bypass this once")
  • Treating hooks as scripts (they're production infrastructure)

# MCP anti-patterns

  • Running MCP servers for capabilities better solved with bash + scripts
  • Letting tool definitions bloat idle context (disable when not in use)
  • Hardcoding credentials in MCP config

# Plugin anti-patterns

  • Submodule-based plugin distribution (not reliably cloned)
  • Distributing plugins that contain hard-coded user paths or secrets

# Quick reference

"Where does this rule belong?"
│
├─ Must be 100%?            → Hook
├─ Path/file-type specific? → Rules file
├─ Always-on identity?      → CLAUDE.md (≤120 lines)
├─ Multi-step workflow?     → Skill
├─ Verbose specialist?      → Subagent
├─ External system?         → MCP
└─ Distribution?            → Plugin

If still unsure, re-read this file and the placement matrix. Defer the decision rather than guess. Misplacement is harder to detect than absence.
