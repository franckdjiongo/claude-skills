# Trigger usage

The user invokes meta-govern by saying:

  • "Set up Claude for this project" → BOOTSTRAP
  • "Audit my Claude setup" / "drift" / "what's missing" → AUDIT
  • "Migrate to new version" / "promote palier" → MIGRATE
  • "Update meta-govern with this new doc" → EVOLVE
  • "What palier am I at" → ADVISE
  • Or explicitly: /meta-govern

# What this means for the user

Every new project from today gets the same baseline: 5 skills, 4 agents, 5 hooks, 8 rules, scripts, sources of truth, evolution roadmap. The user no longer recreates the workflow per project — meta-govern installs it.

Every existing project can be brought up to standards via AUDIT → MIGRATE.

Every model upgrade or new research doc triggers EVOLVE on meta-govern itself; old projects become MIGRATE candidates.

The institutional memory grows in lessons-log.html (append-only). The skill self-evolves; the user is the curator, not the rebuilder.
