# 09 — Troubleshooting reference

Source: §9 of the brief.

The full symptom → cause → fix matrix. When the user reports an error, search
this table by symptom first; if no match, fall back to "Authentication
failures generally" at the bottom.

| Symptom                                                        | Likely cause                                                                                                      | Fix                                                                                                                           | Diagnostic                                                                                      |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 401 `DirectApiAuthorizationRequired`                           | Missing `Authorization` header, or calling legacy SAS URL after migration                                         | Add `Authorization: Bearer <jwt>`; verify trigger setting                                                                     | Inspect URL — no `?sig=` means auth-protected (note: `sig=` may persist in some configurations) |
| 401 `MisMatchingOAuthClaims`                                   | `aud` lacks trailing slash; wrong tenant; wrong scope; or `oid` not in allowlist when _Specific users_            | Use scope `https://service.flow.microsoft.com//.default` (**double slash** — see §11); confirm `tid` and `aud` at jwt.ms       | jwt.ms; sign-in logs filtered by App A                                                          |
| 403 `MisMatchingOAuthClaims` (Self-Host Multitenant URLs)       | `aud` claim missing trailing slash because Entra v2 stripped it from the resource URI                              | Change scope from `https://service.flow.microsoft.com/.default` to `https://service.flow.microsoft.com//.default` (double slash). Full analysis in §11 | Decode the token; confirm `aud` ends in `/`. Run history empty (rejected before flow runs)      |
| 502 `NoResponse`                                                | HTTP trigger has no `Response` action and the call is synchronous                                                  | Add a `Response` action to the flow (Status 200, body) **or** enable the trigger's `Asynchronous Response` setting             | Run history shows the flow ran successfully despite the 502 caller-side                          |
| 401 `DirectApiRequestHasMoreThanOneAuthorization`              | Caller sending both legacy SAS query and `Authorization` header                                                   | Strip `?sp=&sv=&sig=`; keep only `?api-version=2016-06-01`                                                                    | Diff URL against designer                                                                       |
| 401 (generic)                                                  | Missing bearer token, expired token, or wrong audience/issuer/tenant claims                                       | Decode the access token and compare `aud`, `iss`, `tid`, and, when applicable, `oid` to flow requirements; refresh and resend | jwt.ms; `result.expiresOn`                                                                      |
| 403 (no body)                                                  | Trigger uses _Specific users in my tenant_ and caller's `oid` is not allowed                                      | Add SPN Object ID (Enterprise Apps → SPN → Object ID) or UPN                                                                  | Compare `oid` to allowlist                                                                      |
| 403 with body                                                  | Connector or downstream policy rejects authenticated caller                                                       | Check connection / resource permissions; for connectors, inspect connection auth                                              | Connection diagnostics                                                                          |
| Run history shows `Anonymous`                                  | Legacy `Anyone` flow is still active or caller cached old URL                                                     | Disable legacy flow; bust caller URL cache                                                                                    | Filter run history by _Triggered by_                                                            |
| "Anonymous" or unclear caller identity in run history          | Microsoft does not document a guaranteed authenticated-caller field for this trigger                              | Add correlation IDs to client and broker telemetry                                                                            | Plug-in Trace, Application Insights                                                             |
| Invalid audience                                               | Token targets Graph, Dataverse, ARM, or another resource instead of Flow service                                  | Request a token for `https://service.flow.microsoft.com/` (exact match with trailing slash)                                   | Inspect `aud` in jwt.ms                                                                         |
| Wrong tenant                                                   | `tid` doesn't match the maker's tenant                                                                            | Use a same-tenant sign-in / token authority                                                                                   | Inspect `tid` claim                                                                             |
| Expired token                                                  | Cached token past expiry                                                                                          | Refresh token and retry once                                                                                                  | Compare `exp` or library state                                                                  |
| Missing consent                                                | Entra app or connector connection lacks the required delegated consent                                            | Grant admin consent or allow user consent per tenant policy                                                                   | Connection creation prompts; Entra enterprise app consent                                       |
| `AADSTS650053` "scope user_impersonation doesn't exist"        | Connector OpenAPI declared a scope the resource doesn't expose                                                    | Use `User` or `.default` exactly                                                                                              | Connector security tab                                                                          |
| `AADSTS650053` "scope `Users.Read` doesn't exist on resource `7df0a125-...`" | Wrong scope name on the Flow Service first-party app (it doesn't expose `Users.Read`)                              | Use `https://service.flow.microsoft.com/User` (singular, no `.Read`) or the canonical `//.default`                              | Decode the failed token request                                                                  |
| `invalid_client` after successful browser device-code sign-in  | App registration is missing the public-client prerequisites for non-interactive token exchange                     | In Entra → App reg → Authentication: (1) enable **Allow public client flows** AND (2) add a **Mobile and desktop applications** platform with redirect URI `https://login.microsoftonline.com/common/oauth2/nativeclient`. Both are required | The browser shows "You have signed in" but the token endpoint returns invalid_client            |
| Plugin: `Failed to acquire managed identity token`             | FIC subject identifier wrong; missing `subjectscope:1`/`credentialsource:2`                                       | Re-create FIC with `component:pluginassembly,thumbprint:<>,environment:<>`                                                    | Plugin Trace Log; Plugin Identity Manager                                                       |
| Plugin times out at exactly 15 s                               | Sandbox web-access cap                                                                                            | Move long-running work to async webhook / Azure Service Bus; check `ConnectionClose=true`                                     | Plugin Trace Log timestamps                                                                     |
| Conditional Access blocks token                                | CA enforces MFA / compliant device on the resource                                                                | Exclude App A/B from the CA policy or onboard runtime to compliant device — never disable CA tenant-wide                      | Sign-in logs filtered by App ID                                                                 |
| MFA required in non-interactive context                        | Trying noninteractive flow for a user policy that requires interaction; or using ROPC against MFA-enabled account | Use an interactive delegated flow, or move to client_credentials / Managed Identity / **Specific users + SPN**                | Token endpoint or middle-tier returns `interaction_required`                                    |
| Code App: 401 immediately on click                             | Wrong browser profile / incognito                                                                                 | Open the Play URL in the same profile signed into the tenant                                                                  | DevTools network tab                                                                            |
| Code App: `Refused to connect to … CSP directive: connect-src` | Post-30 Jan 2026 CSP enforcement                                                                                  | Wrap in connector (preferred) or allowlist host in PPAC → Environment → Content Security Policy                               | Browser DevTools console                                                                        |
| Custom connector auth not passed to flow                       | Connector set to no auth, wrong resource URI, or wrong connector security setup                                   | Use OAuth 2.0 / Entra ID on the connector and verify the backend resource configuration                                       | Connector Security tab; connection config                                                       |
| CORS failure from model-driven JavaScript                      | Direct browser `fetch` to a cross-origin endpoint without explicit CORS support                                   | Avoid direct browser calls; use custom page + connector or configure CORS on the intermediate API                             | Browser console: blocked preflight, missing `Access-Control-Allow-*`                            |
| Token issued with wrong `aud`                                  | v1 vs v2 endpoint quirks (v2 sometimes emits `aud=<client_id>` for delegated tokens)                              | Always use `/.default` scope; never request resource by client ID                                                             | jwt.ms                                                                                          |
| Token cache misses on every plugin call                        | Sandbox AppDomain recycled per Execute                                                                            | Treat every Execute as cold; do not rely on inter-Execute cache hits                                                          | Inspect `result.AuthenticationResultMetadata.TokenSource`                                       |
| Throttling / transient 429 / 5xx                               | Connector or downstream service limits / transient failures                                                       | Add bounded retry with backoff at the client / broker; respect connection limits                                              | Status codes; connection-rate behavior                                                          |
| DLP policy block                                               | Connector or HTTP-based connector blocked by data policy                                                          | Reclassify or allow the connector in the applicable DLP policy                                                                | Environment data policy review                                                                  |
| Power Platform admin policy enforcement                        | Environment / app access rules, consent settings, or code-app environment settings block usage                    | Adjust environment or tenant policy and republish / recreate the connection as needed                                         | Environment settings; connector availability; Entra consent settings                            |

## Authentication failures generally — diagnostic order

If the symptom doesn't match a row above, walk this list in order:

1. **Did the request reach the flow at all?** Run history empty → caller never
   sent the request, or DLP / network blocked it before it reached Power
   Automate. Check caller logs / network trace.
2. **What status code came back?** 401 = auth, 403 = `oid` allow-list, 4xx
   other = body/payload, 5xx = downstream connector failure.
3. **Decode the request token at https://jwt.ms.** Compare `aud`, `iss`,
   `tid`, `oid` against §1 requirements. The single most common error is
   wrong `aud` (missing trailing slash, or pointing at a connector / Graph
   instead of Flow service).
4. **Is the URL the right one?** Migration regenerates the URL and old SAS
   URLs return 401 forever. Confirm the env-var is pointing at the v2-OAuth
   URL.
5. **Does App A still have admin-consented `User → Access Microsoft Flow`?**
   Tenant admins occasionally revoke consent during cleanups.
6. **Is Conditional Access blocking the token?** Sign-in logs filtered by
   App A's client ID will show a CA failure if so.
