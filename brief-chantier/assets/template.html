Protocole d'échec — arrêt-et-chip

Distinction unique avant d'arrêter : un échec de CODE (causé par les modifications du chantier) = arrêt immédiat ci-dessous ; un échec d'INFRA pré-existant (accès refusé, auth expirée, prompt interactif impossible — reproductible à l'identique sans les modifications du chantier) = chip + terminer les vérifications restantes + rapport honnête qui nomme l'échec verbatim. Dans le doute : échec de code.

  1. Arrête le run au lot en échec. Ne commit pas le lot raté ; laisse les modifications non commitées (le diff est le diagnostic).
  2. Ouvre un chip : spawn_task si disponible, sinon cd ~/Desktop/my-projets/workstation && echo '<JSON>' | bun run chips add - avec {"title","prompt","tldr","cwd"} — le prompt contient : chemin du plan, lot en échec, commande, extrait d'erreur, état laissé, comment reprendre.
  3. Note l'échec dans la conversation hub du plan si elle existe, puis termine proprement (serveurs arrêtés, rapport honnête).
